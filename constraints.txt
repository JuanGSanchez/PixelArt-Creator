# Dependency constraints (reproducibility lock) — PixelArt Creator
# Owner: AGT-09 GitHub/DevOps. Addresses R-11 (dependency-reproducibility gap):
# pyproject.toml's `dependencies` intentionally FLOOR-pins the public install
# contract (PySide6>=6.6, numpy>=1.26, Pillow>=10.0) plus exact-pins two
# compiled deps (pycrdt==0.14.1, websockets==16.0) — that is correct there,
# because `dependencies` is what a downstream installer's resolver sees when
# this package is installed alongside others, and over-pinning it would force
# needless conflicts. Floors stay floors in pyproject.toml; this file is the
# SEPARATE, purpose-built reproducibility mechanism.
#
# WHAT THIS FILE IS: a plain pip constraints file — every package actually
# resolved from a real `pip install -e ".[dev]"`, DIRECT and TRANSITIVE (53
# packages; only 5 are named directly in pyproject.toml's `dependencies`, the
# other ~48 are pulled in underneath them — e.g. anyio/click/jinja2/pyyaml
# arrive via pycrdt/mkdocs, not declared anywhere in the manifest). Pinning
# only the 5 direct deps would leave the harder half of R-11 (transitive
# drift) completely open, so this file covers the full closure instead.
#
# MECHANISM CHOICE, AND WHY: this project uses plain pip with a `[dev]` extra
# and has no lock tool installed (no pip-tools, no uv, no poetry) — see
# design-docs/reports/subagent-report-agt-09-github-devops-lock11-20260730T190000Z.md
# for the fuller comparison. A committed, pip-native constraints file is the
# lowest-friction fit: it needs no new tool to CONSUME (plain `pip install -c`
# is stdlib pip), only to REGENERATE (plain pip is enough for that too — see
# below), and it slots into ci.yml as one extra `-c constraints.txt` flag on
# the existing `pip install -e ".[dev]"` steps with no other workflow change.
#
# WHY ONE FILE CAN SERVE ALL 3 CI RUNNERS (ubuntu-latest / windows-latest /
# macos-latest): this file contains ONLY `name==version` lines — no `--hash`,
# no pinned wheel filenames, no `--platform`/`--only-binary` selectors. pip
# still picks the correct platform/ABI wheel for whichever OS is installing,
# for that pinned VERSION; only the version number is constrained, not the
# artifact. This is safe for THIS project's specific graph because every
# compiled dependency in it (PySide6 — a single abi3 wheel spanning
# CPython 3.10+; numpy; Pillow; pycrdt) is confirmed to publish matching
# version wheels across manylinux x86_64/aarch64, macOS, and Windows at the
# CI-pinned Python 3.12 (research-python313-wheel-availability.md; this
# session's own successful `pip install -e ".[dev]"` resolution below; and
# ci.yml's existing 3-OS quality-gate matrix already installing these same
# floors/pins successfully on all three runners today). A pip constraints
# file also does NOT force-install anything not otherwise required — an
# entry for a package that never gets pulled in on a given OS is simply
# inert there (pip docs: "constraints files ... entries are only used if
# the package is needed by some other requirement"). The one OS-conditional
# transitive package this graph actually has is `colorama` below (pulled in
# by `click`, itself pulled in by `mkdocs`, ONLY under the `sys_platform ==
# "win32"` marker on click's own metadata) — it is listed because it WAS
# resolved on the Windows host that generated this file, and it is inert
# (never installed, never referenced) on the Linux/macOS legs. No
# Linux/macOS-only conditional package was observed in this graph; if a
# future dependency bump introduces one, regenerating on that OS (see below)
# and diffing is how to confirm coverage still holds — a single file is not
# a permanent guarantee, only today's verified state.
#
# COMMAND THAT GENERATED THIS FILE (run 2026-07-30, verbatim, from a clean
# Python 3.12.0 venv — matching ci.yml's pinned `python-version: "3.12"`):
#   py -3.12 -m venv venv-lock
#   venv-lock\Scripts\python.exe -m pip install --upgrade pip
#   venv-lock\Scripts\python.exe -m pip install -e ".[dev]"
#   venv-lock\Scripts\python.exe -m pip freeze | findstr /v "^-e "  > constraints.txt
# (POSIX equivalent: `python3.12 -m venv venv-lock && venv-lock/bin/python -m
# pip install -e ".[dev]" && venv-lock/bin/python -m pip freeze | grep -v
# '^-e ' > constraints.txt`.) The one filtered line was this project's own
# editable self-reference (`-e git+...#egg=pixelart_creator`), which must
# never appear in its own constraints file.
#
# REGENERATE THIS FILE (the one command set above, from main/, with a clean
# Python 3.12 venv active) whenever a manifest dependency changes or the
# transitive graph needs a refresh. Do not hand-edit version numbers.
#
# A DEVELOPER MATCHES CI'S ENVIRONMENT WITH ONE COMMAND (run from main/):
#   pip install -c constraints.txt -e ".[dev]"
