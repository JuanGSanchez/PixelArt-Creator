# ドラッグ&ドロップによるインポート

オペレーティングシステムのファイルエクスプローラー (Windows エクスプローラー、macOS の Finder、Linux の Nautilus) から、
ファイルをそのまま PixelArt Creator のウィンドウの**中**にドラッグすると、そのファイルの種類に合った処理が自動で行われます。
ファイル ▸ 開く、といった面倒な手順は不要です — ウィンドウのどこにドロップしても、ドロップした位置ではなく
**ファイルの種類**によって、アプリが処理を振り分けます。

> **処理の振り分けはファイルの種類で決まり、ドロップした位置では決まりません**。画像は*必ず*新しい
> ドキュメントとして開き、`.pixproj` は*必ず*プロジェクトとして開き、パレットファイルは*必ず*
> アクティブなパレットに読み込まれます — ウィンドウのどこにドロップしても同じです。1 回のドロップで
> 種類を混ぜたり、複数のファイルを同時にドロップしたりすることもできます。

## 画像をドロップする → 新しいドキュメントのタブ

**`.png`、`.jpg`、`.jpeg`、`.bmp`、`.gif`** のいずれかをドロップすると、アクティブになる**まったく新しいキャンバス / ドキュメントのタブ**として開きます。
新しいドキュメントとしてインポートされ、編集中のドキュメントのレイヤーとして追加されることは**ありません** —
現在のドキュメントはそのままです。

- 新しいドキュメントは **RGBA** で、サイズは画像自身の幅と高さです。パレット形式 (インデックスカラー) の PNG や GIF は、
  インポート時に RGBA に展開されます。
- **アニメーション GIF** では、**最初のフレーム**がインポートされます。
- インポートは**ディスク上では読み取り専用**です — ファイルをドロップしても、元のファイルが変更されることはありません。

> **画像サイズの上限**。キャンバスの最大サイズ (**7680 × 4320**) より大きい画像は、エラー通知とともに
> **拒否されます** — 黙ってトリミングされたり拡大縮小されたりすることはありません。先にアプリの外で
> 変換またはリサイズしてください。

## `.pixproj` をドロップする → プロジェクトを開く (保存の確認つき)

**`.pixproj`** をドロップすると、プロジェクトとして開きます。

現在編集中のドキュメントに**未保存の変更**がある場合、アプリは最初に**保存 / 変更を破棄 / キャンセル**の
確認を表示するので、うっかり作業を失うことはありません。

| 選択肢 | 結果 |
| --- | --- |
| **保存** | 現在のドキュメントを保存してから、ドロップしたプロジェクトを開きます。 |
| **変更を破棄** | 保存せずに、ドロップしたプロジェクトを開きます。 |
| **キャンセル** | 開く操作を中止します — 何も変わりません。 |

現在のドキュメントに未保存の変更が**ない**場合 (またはドキュメントが開かれていない場合) は、
確認なしでプロジェクトがすぐに開きます。

## パレットをドロップする → アクティブなパレットに読み込む (元に戻せます)

**`.gpl` (GIMP)、`.hex` (16 進数だけの一覧)、`.pal` (JASC-PAL テキスト)** のいずれかのパレットファイルをドロップすると、
その色がアクティブなドキュメントのパレットを**置き換えます**。

- 置き換えは**元に戻せる 1 ステップ**です。**元に戻す**と、1 回の操作で以前のパレットが正確に復元されます。
- ドキュメントが開かれていない場合、ドロップしても何も起こらず、短い通知が表示されるだけで害はありません。

> **対応しているパレット形式は?** 対応しているのは、ピクセルアートで一般的な**テキスト**形式の
> `.gpl`、`.hex`、`.pal` です。バイナリ形式の **`.aco`** (Adobe) と **`.aseprite`** (Aseprite 独自の形式) は
> **まだ対応していません** — 現時点では、非対応の種類として通知されます。

## 複数のファイルを一度にドロップする

複数のファイルのドロップでは、各ファイルが**独立して、その種類に応じて、ドロップした順に**処理されます。

- 複数の画像 → 複数の新しいタブ。
- `.pixproj` は開かれます (未保存の変更の確認も働きます)。
- パレットは順に読み込まれます — **最後に**ドロップしたパレットが、最終的にアクティブになります (それぞれが個別の元に戻すステップです)。

まとめてドロップしたファイルの中に、種類が不明なファイルや読み取れないファイルがあっても、
通知とともにスキップされ、残りは通常どおり処理されます。ファイルが 0 個のドロップでは何も起こりません。

## ファイルをインポートできないとき

ドラッグ&ドロップでアプリが異常終了することはありません。

- **非対応の種類** (たとえば `.txt` や、`.aco`/`.aseprite` 形式のパレット) は、操作を妨げない短いステータス通知とともに**無視されます**。
- **破損している、デコードできない、またはサイズが大きすぎる**画像、**不正な形式**のパレット、**無効な** `.pixproj` では、
  ファイル名と問題を示す**エラー通知**が表示され、作業内容は**まったく変わらないまま**残ります — 中途半端にできたタブも、
  中途半端に読み込まれたパレットも残りません。

すべての確認と通知は、翻訳可能で、キーボードから操作でき、ライトとダークのどちらのテーマでも読み取れます。

## 対象外の内容

- **レイヤーとしてのインポート** — 画像は常に新しいドキュメントとして開き、現在のドキュメントのレイヤーとして開くことはありません。
- パレット形式の元画像の**インデックスカラーとしてのインポート** — 画像は RGBA にデコードされます。
  インデックスカラーのドキュメントが必要な場合は、あとから**パレット ▸ インデックスカラーに変換**します
  ([レイヤー](layers.md)を参照)。
- **アニメーション GIF のインポート** — インポートされるのは最初のフレームだけです。
- パイプラインの**エクスポート / 書き出し**側 — [エクスポートとパイプライン連携](export-and-pipeline.md)を参照してください。
