# 自動化、マクロ、スクリプト、プラグイン

**自動化システム**を使うと、エディター自身の操作を記録、スクリプト化、再生、一括処理でき、
コンテンツをプロシージャルに生成できます。これらはすべて、
GUI と、GUI なしで動く `pixelart-run` コマンドラインが共有する **1 つ**のエンジンを通じて行われるので、
パネルから実行しても、ビルドスクリプトから実行しても、自動化は**同じ結果**になります。

> **設計によるセキュリティ：`eval` は一切使いません**。スクリプトは、**範囲を限定した、データ駆動のコマンド DSL** であり、
> 任意の Python コードではありません。自動化は*検証済みの操作のリスト* (`{name, params, seed}`) であり、言語ではありません。
> この経路のどこにも、**入力に対する `eval` / `exec` / `compile` / `__import__` は存在しません**。
> そもそも、そこから脱出できるインタープリターがありません。信頼できる 1 つの実行窓口 (ディスパッチャー) が、
> 各操作について、名前が**許可リスト**に載っているか、パラメーターが宣言されたスキーマに合っているかを検査してから、対応する元に戻せるコマンドを組み立てます。

## マクロの記録、再生、`.pixmacro` 形式

**マクロ**パネルは、行った操作を記録し、あとで再生します。

- **マクロを記録**では、各ステップの*入力*、つまり確定したパラメーターと (ランダムな処理では) **シード**を記録します。
  ピクセルの差分は記録しません。記録した内容が、そのまま再生で再実行されます。
- **再生**は、記録した操作を現在のドキュメントに再適用し、**元に戻す 1 ステップ**として扱うので、
  元に戻すとマクロ全体が一度に取り消されます。

マクロは **`.pixmacro`** ファイルとして保存されます。バージョン付きのエンベロープを持つ、ただの JSON です。

```
{
  "format": "pixmacro",
  "schema_version": "1",
  "min_app_version": "0.8.0",
  "api_version": "1",
  "ops": [
    { "op": "batch_recolour", "params": { }, "seed": null },
    { "op": "procgen",        "params": { }, "seed": 12345 }
  ]
}
```

- **`schema_version` / `api_version` / `min_app_version`** は、読み込み時に検査されます。未知のバージョンや未対応のバージョンは、
  マクロを誤って再生するのではなく、**明確なエラーで失敗します**。
- **`params`** は JSON でそのまま表せる型だけで構成されているので、マクロを保存して読み込むと**同一の**マクロが得られます。
  色とインデックスマップはリストとして保持されます。
- **`seed`** は、ランダムなステップのすべてに記録されるので、再生は再現できます。

> **再現可能な再生**。同じ開始ドキュメントに同じマクロを 2 回再生すると、**状態が同一の**ドキュメントになります。
> ランダムなステップはどれも、記録されたシードだけから乱数を取り出し、実時間にも、シードのない乱数にも、
> ロケールにも依存しません。このため、マクロはビルドパイプラインで安心して実行できます。

`.pixmacro` の読み込みは**防御的**です。すべてのフィールドが型、範囲、バージョンの検査を受け、
形式が不正なドキュメントや、範囲外の値を含むドキュメントは、明確なエラーになり、内容が `eval` / `exec` に渡されることは**決してありません**。

## スクリプトの実行

**スクリプトランナー**は、操作のリストを、マクロの再生と同じ信頼できる実行窓口に渡して実行します。
スクリプトの実行は**全か無か**で処理されます。

1. **すべての操作を最初に検証します**。操作名が許可リストに載っているか、パラメーターがスキーマに合っているかが、すべての操作について検査され、
   この検証は**何かを適用する前**に済みます。
2. 実行全体が、**グループ化された、元に戻せる 1 つのコマンド**として適用されます。
3. 途中でいずれかの操作が失敗した場合、適用済みの操作は**逆の順序で巻き戻される**ので、複数の操作から成る実行が失敗しても、
   ドキュメントは**変更されないまま**で、中途半端に適用された状態にはなりません。

実行は 1 つのグループ化されたコマンドなので、完了したスクリプトは**元に戻す 1 ステップ**です。

## プラグインのマネージャー、同意、信頼モデル

**プラグイン**パネルは、プラグインを一覧表示し、ユーザーがマニフェストを読み込んだプラグインごとにその権限を表示し、
プラグインの有効化と無効化を行います。プラグインは、新しい DSL の操作を登録することでエディターを拡張するためのものです。
**このリリースでは、アプリにはプラグインのコードを読み込んだり実行したりする処理はありません**。
プラグインの検出、マニフェストの読み込み、有効化、無効化のどれも、プラグインを呼び出すことはありません。
マニフェストが宣言する権限は、プラグインの想定される用途を表すものであり、
プラグイン自身のコードにできることを制限するものではありません (下の注記を参照)。

- **検出は、プラグインを一覧に表示するだけです**。アプリは、標準の Python エントリポイントを通じて
  インストール済みのプラグインを見つけますが、読み取るのは名前とバージョンだけで、そのコードは読み込みも実行も**しません**。
  検出されたプラグインは、アプリが権限をプラグイン自体から読み取らないため、権限が表示されず、有効にすることもできません。
  権限の取得元は、ユーザーがディスクからパネルに追加するマニフェストファイルで、そのファイルは一覧に独立した項目として表示されます。
  アプリは、マニフェストがインストール済みのプラグインのものであるかどうかを確認しません。
- **同意の対象はマニフェストであり、プラグインのコードではありません**。**有効にする**では、
  マニフェストが宣言する権限を表示し、確認を求めます。権限は、ユーザーが全体をまとめて許可するか、プラグインを有効にしないかのどちらかです。
  アプリは、マニフェストをプラグインのコードが実際に行う内容と照合しません。
  有効にすると、ユーザーが許可した権限をメモリに記録し、プラグインを有効な状態にします。
  アプリにはプラグインのコードを実行する処理がないので、有効にしても、アプリがそのコードを実行することはありません。
  ユーザーの同意は保存されないため、エディターを閉じると、すべてのプラグインが再び無効になります。
  このリリースには、有効化時に実行するコードを、プラグインを扱うアプリ側の部分 (プラグインホスト) に渡すものは何もありません。
  プラグインホストは、仮にその呼び出し元が有効化時に実行するコードを渡した場合には、そのコードに権限オブジェクトを渡し、
  そのオブジェクトを通じた呼び出しのうちユーザーが許可していないものを拒否するように作られていますが、このリリースではこの拒否が行われることはありません。
  そのオブジェクトを通じて登録された操作には先頭にプラグインの名前が付くので、組み込みの操作の名前と同じにはなりません。
  また、そのオブジェクトを通じた読み取り権限での呼び出しは、渡されたドキュメントをコピーではなくそのまま返します。
  そのオブジェクトを通さないコードは、その制限を受けず、組み込みの操作を含め、操作を直接登録したり削除したりできます。
- **無効にしても、取り除かれるのは操作であり、プラグインのコードではありません**。**無効にする**では、
  権限オブジェクトを通じて登録された操作の登録を解除します。このリリースでは、操作を登録するものが何もないので、解除される操作はありません。
  プラグイン自身のコードがすでに行ったことを元に戻すことはありません。

> **プラグインはサンドボックス化されていません**。プラグインはコンピューターから分離されておらず、
> このリリースでは、アプリはどのプラグインに対しても分離を行いません。
> プラグインをインストールすると、ほかの人の Python コードがコンピューターに置かれ、
> アプリはそのインストールを行うことも、インストールされる内容を検査することもありません。
> また、パッケージは、そのパッケージがインストールされた環境で Python が起動するたびにコードを実行するよう、Python に要求することもできます。
> その環境にはエディターも含まれるので、**プラグイン**パネルを一度も開かなくても、
> プラグインをインストールしただけで、そのコードが実行されることがあります。
> エディター自身のプロセスで実行されるコードは、どのような経路でそこに入ったかにかかわらず、
> プラグインが宣言した権限に関係なく、エディター自体と同じようにユーザーのファイルとネットワークにアクセスできます。
> ご自身が信頼するプラグインだけをインストールして有効にしてください。

## 一括色替え

**一括色替え**は、**複数の対象に同時に**、1 つの色の置き換えを適用します。
これは**全か無かで適用され、元に戻せる 1 つのコマンド**として扱われます。

- **インデックスカラー**の対象ではパレットのインデックスを置き換え (`old_index → new_index`)、
  **RGBA** の対象では色を置き換えます (`old_rgba → new_rgba`)。エディターの既存の色替え操作を再利用するので、
  一括処理に含めた対象は、同じ対応でその対象だけを色替えした場合と**バイト単位で同一**になります。
- **全か無か**で処理されます。すべての対象が検証され、対象ごとのステップが組み立てられるのは、**何かを適用する前**です。
  無効な対象があると、その対象を名指しして失敗し、**変更はまったく行われません**。一括処理全体が**元に戻す 1 ステップ**です。

## プロシージャル生成

**プロシージャル生成**パネルは、生成したコンテンツで領域を埋めます。アプリ独自に実装された、**シード付き**のジェネレーターが
5 種類あります。

| ジェネレーター | 生成されるもの |
| --- | --- |
| **バリューノイズ** | シードから作られる、値のグリッドによるノイズ。 |
| **グラデーションノイズ** | パーリンノイズ方式の勾配ノイズ。 |
| **OpenSimplex ノイズ** | 特許上の問題がない、シンプレックスグリッドによる勾配ノイズ。 |
| **セルオートマトン** | セルオートマトンによるパターン。 |
| **ディザグラデーション** | 2 色のなめらかなグラデーションをドキュメントのパレットにディザリングして適用するので、結果はパレットの範囲内に収まります。 |

どのジェネレーターも、**パラメーターとシードだけで決まる純粋な関数**です。同じシードと同じパラメーターからは、
常に同じ出力が得られます。生成した内容は**元に戻せるコマンドの経路**で書き込まれるので、どの生成も元に戻す 1 ステップです。
出力は、軸ごとに、プラットフォームが定めるプロシージャル生成のサイズ上限までに制限されます。

## 元に戻せることと応答性

自動化は、マクロの再生、スクリプトの実行、一括色替え、プロシージャル塗りつぶしのいずれも、
**通常の元に戻すスタックに 1 ステップとして**積まれるので、どれでも取り消せます。GUI では、自動化は
**バックグラウンド**で動作し、終了時の後始末も毎回同じように行われるので、
長い一括処理や大きなプロシージャル塗りつぶしでもウィンドウが固まりません。

## `pixelart-run` コマンドライン

自動化や CI のために、`pixelart-run` は `.pixmacro` を `.pixproj` に対して、**GUI なしで**再生します。
GUI が使うのと**まったく同じ**信頼できる実行窓口を通すので、得られるドキュメントは、
同じ入力に対して同じ自動化を GUI で実行した場合と**状態が同一**です。

```
pixelart-run --input PROJECT.pixproj --macro MACRO.pixmacro --output OUT.pixproj [options]
```

| フラグ | 意味 |
| --- | --- |
| `--input PATH` | **(必須)** マクロを適用する元の `.pixproj` プロジェクト。 |
| `--macro PATH` | **(必須)** 再生する `.pixmacro` マクロ。 |
| `--output PATH` | **(必須)** 結果を書き込む `.pixproj` のパス。 |
| `--seed N` | シードが記録されていない操作のシードを上書きします (記録されたシードが常に優先されます)。 |
| `--param KEY=VALUE` | マクロのパラメーターを追加または上書きします。繰り返し指定できます。 |

**終了コード**：`0` は成功、`1` は自動化の失敗 (スクリプト / マクロ / 一括処理 / プロシージャル生成のエラー、
または書き込みの失敗)、`2` は引数が正しくない場合、または入力のプロジェクトやマクロが不正または読み取れない場合です。

> **コンソールのエントリポイント**。`pixelart-run` は、`pip install` 時にコンソールスクリプトとしてインストールされます。

## 対象外の内容

- **任意の Python スクリプト**は**設計上サポートしません**。スクリプトは範囲を限定した、許可リスト方式のコマンド DSL であり、
  汎用のインタープリターではありません。これは意図的なセキュリティ上の境界であり、いずれ取り除かれる制限ではありません。
- **信頼できないサードパーティ製プラグインの分離**は**今後の対応**です。このリリースでは、プラグインはサンドボックス化されていません。
  ご自身が信頼するプラグインだけをインストールして有効にしてください。
