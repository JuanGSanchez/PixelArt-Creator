# アセットライブラリ: 閲覧、タグ付け、検索

**アセットライブラリ**は、再利用できるアセット (スプライト、アニメーション、タイルセット、タイルマップ、パレット) を
1 か所にまとめた、スタジオ全体のカタログです。すでに作成した要素を**名前付きのアセット**として登録し、
自由形式の**タグ**で整理し、**検索とフィルター**で目的のものをすばやく見つけられます。
ライブラリと 3 つのパネルは、**ライブラリ**メニューから使います。

> **アセットとは**。アセットは、すでに作成した要素の 1 つを*参照*する**カタログのエントリ**です。
> 作品のコピーがもう 1 つ作られるわけではありません。各エントリは、**固定の ID**、**種類** (スプライト、アニメーション、
> タイルセット、タイルマップ、パレットのいずれか)、表示用の**名前**、**タグ**、少量のメタデータを持ちます。
> エントリが指すのは、その要素の正式な保存形式 (アプリのほかの部分が使うのと同じ `.pixproj` のデータ) です。
> 作品そのものについて、ライブラリが新しい保存形式を追加することはありません。

## ライブラリを開く

**ライブラリ**メニューには、次の 3 つのパネルそれぞれを表示または非表示にする、ドックの切り替えがあります。

| メニュー項目 | パネル | 用途 |
| --- | --- | --- |
| **アセットライブラリ** | カタログの一覧 | 名前、種類、タグですべてのアセットを閲覧します。 |
| **アセット検索** | 検索 / フィルターのコントロール | 名前、タグ、種類のいずれか 1 つ以上で一覧を絞り込みます。 |
| **アセットのタグ付け** | タグエディター | 選択したアセットのタグを追加、削除します。 |

各項目は通常のドック切り替えです (アプリのほかのワークフローのパネルと同じです)。3 つのパネルは、好きなように配置できます。
パネルは、メモリ上の **1 つ**のカタログを共有するので、1 つのパネルで加えた変更は、すぐにほかのパネルにも反映されます。

## アセットを登録する

カタログに何かを表示するには、先に**登録**する必要があります。アプリ内の 3 か所から登録を開始でき、
いずれも共通の**アセットを登録**ダイアログにたどり着きます。

- **アクティブなドキュメントを登録**は、**ライブラリ**メニューにあり、アクティブなタブで開いているドキュメントを登録します。
  あとで同じドキュメントをもう一度登録すると、重複を作る代わりに、既存のカタログエントリに新しいリビジョンが追加されます。
  詳しくは、[アセットのバージョン管理とプロジェクト間の再利用](asset-versioning.md)を参照してください。
- **選択範囲を登録**も、**ライブラリ**メニューにあり、現在の選択範囲の内側にあるピクセルだけを登録します。
  矩形でない選択範囲では、登録されるアセットで、選択されたピクセルの外側はすべて透明になります。
  何も選択していない場合、登録するものはありません。
- **アセットライブラリにも追加**は、エクスポートダイアログ ([エクスポートとパイプライン連携](export-and-pipeline.md)を参照) のチェックボックスです。
  オンにすると、エクスポートと同時に、エクスポートしたファイルがライブラリに登録されます。

3 つとも、同じ**アセットを登録**ダイアログが開き、次の項目を入力します。

| 項目 | 入力する内容 |
| --- | --- |
| **名前** | 新しいカタログエントリの表示名。 |
| **種類** | 5 種類のアセットのいずれか：スプライト、アニメーション、タイルセット、タイルマップ、パレット。 |
| **タグ** | 任意のタグ (カンマ区切り)。下記のタグ付けパネルと同じ長さと個数の上限が検査されます。 |

ダイアログは、入力中に検証を行います。名前が空の場合や、タグの集合が長さ / 個数の上限を超えている場合は、
**登録**ボタンが無効になり、修正するまで理由がはっきり表示されます。ダイアログをキャンセルすると、何も登録されません。

## アセットを 1 つずつインポート / エクスポートする

**ライブラリ**メニューのさらに 2 つのコマンドは、プロジェクト全体ではなく、1 つのアセットファイルを移動します。

- **アセットをエクスポート**は、現在選択しているカタログエントリ (何も選択していない場合は、開いているカタログのすべてのエントリ) を、
  インポートできる 1 つのアセットファイルとしてエクスポートします。
- **アセットをインポート**は、そのようなファイルを開いているライブラリに読み込み、カタログにマージします。

これらは、プロジェクト全体と、そのプロジェクトが参照するすべてを移動する
**プロジェクトバンドルをエクスポート** / **プロジェクトバンドルをインポート**とは別のものです。
詳しくは、[アセットのバージョン管理とプロジェクト間の再利用](asset-versioning.md)を参照してください。

## カタログを閲覧する

**アセットライブラリ**パネルは、カタログを**名前**、**種類**、**タグ**、**状態**の 4 列で一覧表示します。
カタログの内容がそのまま表示され、アセットの追加、削除、タグ付けは、一覧にすぐ反映されます。
行を選択するとそのアセットが選ばれ、**アセットのタグ付け**パネルはそのアセットを編集します。

- 一覧は共有のカタログだけで決まり、パネル自体は独自のフィルタリングも並べ替えも行いません。
- **アセット検索**パネルに有効な検索条件があるときは、ライブラリの一覧には一致するエントリだけが表示されます (下記を参照)。
  条件をクリアすると、完全な一覧に戻ります。

## アセットにタグを付ける

**アセットのタグ付け**パネルは、ライブラリで選択したアセットのタグを編集します。タグを入力して追加し、タグを選択して削除します。
タグは自由形式のラベルで、たとえば `hero`、`enemy`、`tileset-a` のように、意味でアセットを整理できます。

- **タグの編集は元に戻せます**。タグの追加と削除はどちらも共有の元に戻すスタックの 1 ステップなので、
  **元に戻す**で以前のタグの集合が正確に復元され、**やり直す**で編集が再び適用されます。
  これはほかの場面で使うのと同じ元に戻す / やり直す操作です ([はじめにとワークスペース](app-basics.md)を参照)。
- **すでにあるタグを追加しても何も起こりません** (何もしない操作です)。存在しないタグを削除しても同様に無害です。
- **タグには上限があります**。1 つのタグの長さには最大があり、1 つのアセットが持てるタグの数にも最大があります。
  長すぎるタグや、アセットのタグ数の上限を超えるタグは、**わかりやすいメッセージで拒否**され、追加されません。
  何かが黙って切り詰められることはありません。

## 検索とフィルター

**アセット検索**パネルは、連動する 3 つのコントロールで、ライブラリの一覧を絞り込みます。

| コントロール | 一致の条件 |
| --- | --- |
| **名前** | 入力したテキストを名前に*含む*アセット (部分一致)。 |
| **タグ** | 入力したタグを持つアセット (複数入力する場合はカンマ区切り)。 |
| **種類** | 選択した種類のアセット。**すべての種類**を選ぶと、種類のフィルターが解除されます。 |

- 3 つのフィルターは、**すべてを満たす** (AND) 条件になります。結果は、設定した名前*かつ*タグ*かつ*種類に一致する必要があります。
  空のままにしたコントロールの条件は無視されます。
- **結果は安定しており、毎回同じになります**。同じカタログと同じ検索条件からは、常に同じ一覧が同じ順序で得られます。
- **すべてのコントロールをクリアすると、通常の順序で完全なカタログに戻ります**。

> **ファイルではなく意味で探す**。アセットにタグが付いていて検索できるので、フォルダーを探し回らなくても、
> 「`enemy` のスプライトすべて」や「`dungeon` のタグが付いたタイルセット」をすぐに呼び出せます。
> アセットに付けるタグの語彙を小さく一貫したものにしておけば、あとはフィルターが担当します。

## アセットの保存方法

内部では、ライブラリは、アセットのエントリの**カタログ**と、そのバイト列のための**コンテンツアドレス方式のストア**を保持しています。

- **内容に基づいて 1 度だけ保存されます**。各アセットのバイト列は、*内容*そのものをキーとして保存されるので、
  同じ内容を 2 回登録しても複製されず、同一のバイト列は 1 つしか保持されません (**重複排除**)。
- **パスではなく、固定の ID で参照されます**。アセットは、アセットとともに移動する固定の ID で識別されるので、
  元のファイルを**移動したり名前を変更したり**しても、カタログのエントリは**壊れません**。
- **作品は通常の保存形式のままです**。カタログは、既存の `.pixproj` プロジェクト形式をデータとして再利用し、
  参照とメタデータだけをその横に保存します。作品のために気にすべき第 2 の形式はありません。
- **読み込みは防御的です**。カタログやそのメタデータは、読み込み時に信頼できない入力として扱われます。
  サイズと形のチェックが行われ、何かが実行されることはなく、参照されるパスはすべてライブラリの内側に収まっていることが確認されます。
  形式が不正なカタログや、範囲外の値を含むカタログは、異常終了したり何かを壊したりする代わりに、明確なエラーで拒否されます。

## アセットライブラリのそのほかの機能

アセットライブラリは、段階に分けて提供されてきました。現在は、予定していた機能のすべてが利用できます。
上記のカタログ、タグ付け、検索 / フィルターに加えて、次の機能があります。

- **[アセットの依存関係と参照切れの検出](asset-dependencies.md)** — アセットどうしの参照関係を調べられるグラフ
  (`sprite -> animation -> tileset -> tilemap`) と、あるアセットを変更したことで、それを参照する別のアセットが壊れたときの受動的な警告です。
- **[アセットのバージョン管理とプロジェクト間の再利用](asset-versioning.md)** — アセットごとの追記専用のリビジョン履歴 (確認と復元)、
  共有アセットをコピーではなく参照としてプロジェクト間で再利用すること、プロジェクトが参照するアセットを自己完結したバンドルとして
  エクスポート / インポートすること、そして共有データを任意でクラウドに保管する機能 (このリリースでは接続されていません) です。
