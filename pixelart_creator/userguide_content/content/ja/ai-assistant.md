# AI アシスタント — チャットでエディターを操作する

**AI アシスタント**を使うと、エディターを**普通の言葉**で操作できます。チャットパネルにやりたいことを入力すると、
アシスタントはアプリ**自身**の操作を実行して処理します。それは、手作業で記録、スクリプト化、一括処理できる
[自動化](automation-and-scripting.md)のコマンドと同じものです。**モデルに依存しない**設計で、好きな AI プロバイダーを指定し、
自分の API キーを用意して使います。また**任意**の機能なので、設定しなくてもアプリは問題なく使えます。

> **アシスタントは安全な自動化レイヤーを通じて動作し、新しい入り口が増えることはありません**。アシスタントが行う操作はすべて、
> 許可リストに載った通常のエディター操作で、マクロやスクリプトが使うのと**同じ**、信頼できる `eval` 不使用のコマンドレイヤーを
> 通じて実行されます。任意のコードを実行することも、そのコマンドレイヤーの外に手を伸ばすことも、新しい権限を作り出すこともできません。
> チャットのメッセージは**データ**であり、エディターが安全にはできないことをさせる許可証にはなりません。

## アシスタントを開く

チャットパネルは、**ヘルプ ▸ AI アシスタント**から開きます。パネルは**ドッキングできるパネル**で、キャンバスの隣に置けるので、
作品を見ながらアシスタントの作業を確認できます。パネルには、進行中の会話が表示されます。
ユーザーのメッセージ、アシスタントの返信、アシスタントがドキュメントに加えた編集です。

アシスタントがプロバイダーと通信できるようにするには、先に**プロバイダーを設定**する必要があります (下記を参照)。
それまでは、エラーになるのではなく、わかりやすい**未設定**の状態で待機します。プロバイダーの設定は 1 回だけ行えば済みます。

## プロバイダーとキーの設定

プロバイダー設定ダイアログは、AI アシスタントパネルの**設定…** ボタンで開きます。アシスタントは**モデルに依存しない**ので、
使いたいサービスとモデルを選び、次の項目を入力します。

| 項目 | 入力する内容 |
| --- | --- |
| **プロバイダー** | **OpenAI 互換**のサービスか、**Anthropic (Claude)** のいずれかです。OpenAI 互換のオプションは幅広いエンドポイント (OpenAI 自体、Gemini の OpenAI 互換エンドポイント、Ollama や llama.cpp などのローカルランタイム) に対応し、Anthropic のオプションは Claude とネイティブな API で直接通信します。 |
| **エンドポイント URL** | サービスの API エンドポイント。ホスト型のプロバイダーか、自分のマシン上のローカルなモデルサーバーを指定します。 |
| **モデル** | 使用するモデルの名前。選んだプロバイダーでの呼び名で入力します。 |
| **API キー** | プロバイダー用のキー。ローカルのモデルサーバーであっても、キーを保存する必要があります。アシスタントは、エンドポイントと空でないキーの両方が保存されているときだけ、プロバイダーを設定済みとみなし、入力された内容を確認せずにそのまま送信します。ローカルサーバーがキーを確認しない場合は、受け付けられる任意の文字列 (空でないもの) を入力してください。 |

**保存**を選択すると、プロバイダーの設定が保存されます。

> **キーは安全に保存され、プロジェクトには決して含まれません**。入力した API キーは、
> **オペレーティングシステムの安全な認証情報ストア (OS のキーリング)** に渡されます。
> **プロジェクトファイル (`.pixproj`) に書き込まれることも、ログに記録されることも、共有またはエクスポートしたプロジェクトとともに渡ることも一切ありません**。
> したがって、プロジェクトを共有しても、キーが共有されることはありません。キーへのライブアクセスには、
> オプションの extra (`pip install ".[assistant_live]"`) を使います。README を参照してください。

> **認証情報は任意です**。アシスタントは完全にオプトインです。プロバイダーを設定しなければ、エディターのほかの部分は何も変わらず、
> アシスタントを使わないだけです。サインインを強制されることはなく、PixelArt Creator の利用にキーは不要です。

## チャットでワークフローを進める

プロバイダーの設定 (エンドポイントと、キーリングに保管された API キー) を保存したら、自然な言葉でリクエストを入力して送信します。
たとえば、領域の色替えやプロシージャルコンテンツの生成を依頼できます。
アシスタントは依頼を解釈し、どのエディター操作で実現できるかを判断して実行し、実行した内容を会話の記録で報告します。
**実際**のエディター操作を動かしているので、結果は、そのステップを自分で実行した場合とまったく同じになります。

モデルとのやり取りは**バックグラウンド処理**で実行されるので、アシスタントが処理している間もウィンドウは反応し続けます。

## 段階的な安全性 — 元に戻せる操作は自動で実行、破壊的な操作は先に確認

アシスタントは、実行したいすべての操作を 2 つの段階のどちらかに分類し、どちらになるかによって、ユーザーの確認が必要かどうかが決まります。
この判定はアプリ自身のコードの中にあり、AI モデルが決めるものでは**ありません**。チャットのメッセージの書き方で、
エディターにこの判定をやめさせることもできません。

- **元に戻せる操作はすぐに適用されます**。通常の[元に戻すスタック](app-basics.md)に、きれいに取り消せる 1 ステップとして積まれる操作
  (一括色替えやプロシージャル塗りつぶしなど) は、**確認なしで適用されます**。ドキュメントに反映されるのが見え、
  ほかの編集と同じように**元に戻せます**。
- **破壊的な操作は先に確認します**。元に戻せる操作の一覧にないものはすべて、**既定で破壊的**とみなされ、
  アシスタントは**一時停止して**、その操作を具体的に示してユーザーに尋ねます。
  **確認した場合にのみ**実行され、そうでなければキャンセルされます。破壊的な操作が黙って適用されることはありません。

> **既定で安全です**。この判定は、きれいに元に戻せると確実にわかっていない操作については、既定で*確認する*側に倒れます。
> そのため、新しい操作や珍しい操作が、まだ誰も分類していないという理由だけで自動実行をすり抜けることはありません。
> 元に戻せる段階は小さく、明示的に決められた集合で、それ以外はすべて確認のプロンプトが必要です。

## アシスタントにできないこと

- **任意のコードは実行できません**。アシスタントが動かせるのは、信頼できるコマンドレイヤーを通した、許可リストに載ったエディター操作だけで、
  この経路に `eval` / `exec` はありません。[マクロとスクリプト](automation-and-scripting.md)の場合とまったく同じです。
- **確認の仕組みを迂回できません**。ツールの結果の中に紛れ込んだ指示を含め、どのような指示でも、
  破壊的な操作に確認を省かせることはできず、許可されていない操作は、会話がそれを求めたというだけでは実行できません。
- **キーが漏れることはありません**。認証情報は OS のキーリングに保管され、ユーザーが設定したプロバイダーとの通信にだけ使われます。

## アクセシビリティ、テーマ、言語

アシスタントパネルとプロバイダーダイアログのコントロールにはすべて、支援技術に伝わる名前が付いていて、キーボードから操作できます。
ラベルはすべて完全に翻訳可能で、言語を切り替えると自動で更新されます。
どちらの画面も、ライトとダークのどちらのテーマでも正しく表示されます。
