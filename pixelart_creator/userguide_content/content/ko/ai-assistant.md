# AI 어시스턴트 — 대화로 편집기 조작하기

**AI 어시스턴트**를 쓰면 **평범한 말**로 편집기를 조작할 수 있습니다. 대화 패널에 원하는 작업을
입력하면, 어시스턴트가 앱 **자체의** 작업을 실행해 처리합니다. 직접 기록하고, 스크립트로 짜고,
일괄 처리할 수 있는 [자동화](automation-and-scripting.md) 명령과 같은 작업입니다. 특정 모델에 묶여
있지 않아서 원하는 AI 제공자를 지정하고 자신의 키를 입력하면 됩니다. 또한 **선택 사항**이므로
설정하지 않아도 앱을 완전히 쓸 수 있습니다.

> **어시스턴트는 안전한 자동화 계층을 통해 동작하며, 새로 노출되는 기능은 없습니다.** 어시스턴트가
> 하는 모든 동작은 허용 목록에 있는 평범한 편집기 작업이며, 매크로와 스크립트가 쓰는 **동일하며
> `eval`이 없는, 신뢰할 수 있는** 명령 계층을 통해 전달됩니다. 임의의 코드를 실행하거나, 그 명령
> 계층을 우회하거나, 새로운 권한을 만들어 낼 수 없습니다. 대화 메시지는 **데이터**일 뿐이며,
> 편집기가 안전하게 할 수 없는 일을 하라는 허가증이 아닙니다.

## 어시스턴트 열기

**어시스턴트** 메뉴에서 대화 패널을 엽니다. 캔버스 옆에 배치할 수 있는 **도킹 패널**로 나타나므로,
작품을 계속 보면서 어시스턴트가 작업하는 모습을 지켜볼 수 있습니다. 패널에는 진행 중인 대화, 즉
사용자의 메시지, 어시스턴트의 답변, 어시스턴트가 문서에 가한 편집이 표시됩니다.

어시스턴트가 제공자와 통신하려면 먼저 제공자를 **구성**해야 합니다(아래 참고). 구성하기 전에는
오류를 내는 대신 분명한 **구성되지 않은** 상태로 남아 있으며, 제공자 구성은 한 번만 하면 됩니다.

## 제공자와 키 구성하기

**어시스턴트** 메뉴에서 제공자 구성 대화 상자를 엽니다. 어시스턴트는 특정 모델에 묶여 있지 않으므로,
원하는 서비스와 모델을 고르고 다음을 입력합니다.

| 필드 | 입력할 내용 |
| --- | --- |
| **제공자** | **OpenAI 호환** 서비스 또는 **Anthropic (Claude)** 중 하나입니다. OpenAI 호환 옵션은 OpenAI 자체, Gemini의 OpenAI 호환 엔드포인트, Ollama나 llama.cpp 같은 로컬 런타임 등 폭넓은 엔드포인트를 지원하며, Anthropic 옵션은 Claude와 직접 통신합니다. |
| **엔드포인트 URL** | 서비스의 API 엔드포인트입니다. 호스팅되는 제공자나 자신의 컴퓨터에서 실행 중인 로컬 모델 서버를 가리키게 하세요. |
| **모델** | 선택한 제공자가 쓰는 모델 이름 그대로입니다. |
| **API 키** | 제공자의 키입니다(제공자가 요구하는 경우에만 필요하며, 로컬 모델 서버는 필요하지 않을 수 있습니다). |

**연결**을 선택하면 이번 세션에서 그 제공자가 활성화됩니다.

> **키는 안전하게 저장되며, 프로젝트에는 저장되지 않습니다.** 입력한 API 키는 **운영 체제의 보안 자격
> 증명 저장소**(OS 키링)로 전달됩니다. 키는 프로젝트 파일(`.pixproj`)에 **기록되지 않고, 로그에 남지
> 않으며, 공유하거나 내보낸 프로젝트와 함께 이동하지도 않습니다**. 따라서 프로젝트를 공유해도 키가
> 공유되는 일은 없습니다. 실제 키 접근에는 선택 사항인 추가 구성 요소(`pip install ".[assistant_live]"`)가
> 필요합니다. README를 참고하세요.

> **자격 증명은 선택 사항입니다.** 어시스턴트는 전적으로 사용자가 선택해서 쓰는 기능입니다. 제공자를
> 구성하지 않아도 편집기의 다른 부분은 전혀 달라지지 않으며, 어시스턴트를 쓰지 않을 뿐입니다.
> 로그인을 강요하지 않고, PixelArt Creator를 쓰는 데 키도 필요하지 않습니다.

## 대화로 작업 흐름 조작하기

제공자가 연결되면 자연어로 요청을 입력해 보냅니다. 예를 들어 어떤 영역의 색상을 바꾸거나 절차적
콘텐츠를 생성해 달라고 요청할 수 있습니다. 어시스턴트는 요청을 해석하고, 어떤 편집기 작업으로
달성할지 정해 실행한 뒤, 무엇을 했는지 대화 내용에 알려 줍니다. **실제** 편집기 작업을 실행하므로,
결과는 사용자가 그 단계를 직접 수행했을 때와 정확히 같습니다.

모델 호출은 **백그라운드 작업 스레드**에서 실행되므로, 어시스턴트가 생각하는 동안에도 창은 계속
반응하며, 긴 요청은 취소할 수 있습니다.

## 등급별 안전장치 — 되돌릴 수 있는 동작은 자동 실행, 파괴적 동작은 먼저 확인

어시스턴트는 하려는 모든 동작을 두 등급 중 하나로 분류하며, 그 등급에 따라 사용자 확인이 필요한지
정해집니다. 이 관문은 앱 자체 코드에 있어서 AI 모델이 정하는 것이 **아니며**, 대화 메시지의 어떤
표현으로도 편집기가 이를 건너뛰게 할 수 없습니다.

- **되돌릴 수 있는 동작은 바로 적용됩니다.** 일반 [실행 취소 스택](app-basics.md)에 깔끔하게 취소되는
  한 단계로 쌓이는 동작(예: 일괄 색상 변경, 절차적 채우기)은 **묻지 않고 적용됩니다**. 문서에서 적용되는
  모습을 볼 수 있고, 다른 편집과 마찬가지로 **실행 취소**할 수 있습니다.
- **파괴적 동작은 먼저 묻습니다.** 되돌릴 수 있는 동작 목록에 없는 동작은 모두 기본적으로 **파괴적**
  동작으로 취급되며, 어시스턴트는 **멈추고** 정확한 동작 이름을 밝히며 확인을 요청합니다. 사용자가
  **확인한 경우에만** 실행되고 그렇지 않으면 취소되므로, 파괴적 동작이 조용히 적용되는 일은 없습니다.

> **기본값은 안전입니다.** 이 관문은 깔끔하게 되돌릴 수 있다고 확실히 알려지지 않은 모든 동작에
> 대해 기본적으로 *묻습니다*. 그래서 새롭거나 특이한 동작이 아무도 분류하지 않았다는 이유만으로
> 자동 실행되는 일은 있을 수 없습니다. 되돌릴 수 있는 등급은 작고 명시적인 집합이며, 나머지는 모두
> 확인 창을 거칩니다.

## 어시스턴트가 하지 않는 일

- **임의의 코드를 실행할 수 없습니다.** 어시스턴트는 편집기의 허용 목록 작업만 신뢰할 수 있는 명령
  계층을 통해 조작하며, 이 경로에는 `eval`/`exec` 호출이 없습니다.
  [매크로와 스크립트](automation-and-scripting.md)와 마찬가지입니다.
- **확인 관문을 우회할 수 없습니다.** 도구 결과 안에 담겨 들어온 지시를 포함해, 어떤 지시도 파괴적
  동작이 확인을 건너뛰게 할 수 없습니다. 대화에서 요청한다는 이유만으로 허용되지 않은 작업이 실행되는
  일도 없습니다.
- **키를 유출하지 않습니다.** 자격 증명은 OS 키링에만 보관되며, 사용자가 구성한 제공자와 통신하는
  데에만 쓰입니다.

## 접근성, 테마, 언어

어시스턴트 패널과 제공자 대화 상자의 모든 컨트롤에는 접근 가능한 이름이 있고 키보드로 접근할 수
있습니다. 모든 레이블은 완전히 번역할 수 있고 언어를 바꾸면 즉시 다시 번역되며, 두 화면 모두
라이트 테마와 다크 테마에서 올바르게 표시됩니다.

## 관련 주제

- 어시스턴트는 [자동화 시스템](automation-and-scripting.md)의 나머지 기능, 즉 매크로, 스크립트, 일괄
  색상 변경, 절차적 생성과 같은 작업을 조작합니다.
- 제공자 구성은 [클라우드 저장소](cloud-and-collaboration.md)에서 쓰는 방식과 같습니다. 자격 증명은
  선택 사항이고 키링에 저장합니다.
