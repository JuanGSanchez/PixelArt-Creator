# 끌어다 놓기로 가져오기

운영 체제의 파일 탐색기(Windows 탐색기, macOS Finder, Linux Nautilus)에서 파일을 PixelArt Creator
창 **안으로** 바로 끌어다 놓으면, 앱이 그 종류의 파일에 알맞게 처리합니다. 파일 ▸ 열기…를 거치는
번거로움이 없습니다. 창 어디에든 놓으면 앱이 놓은 위치가 아니라 **파일 형식에 따라** 처리합니다.

> **처리 방식은 위치가 아니라 형식으로 정해집니다.** 이미지는 *항상* 새 문서로 열리고, `.pixproj`
> 파일은 *항상* 프로젝트로 열리며, 팔레트 파일은 *항상* 활성 팔레트로 불러와집니다. 창의 어느
> 곳에 놓든 마찬가지입니다. 여러 형식을 섞어서, 또는 여러 파일을 한꺼번에 놓을 수도
> 있습니다.

## 이미지 놓기 → 새 문서 탭

**`.png`, `.jpg`, `.jpeg`, `.bmp`, `.gif`** 파일을 놓으면 활성 상태가 되는 **완전히 새로운 캔버스 /
문서 탭**으로 열립니다. 편집 중인 문서의 레이어가 **아니라** 새 문서로 가져오므로, 현재 문서는
그대로입니다.

- 새 문서는 이미지의 가로, 세로 크기를 그대로 가진 **RGBA** 문서입니다. 팔레트를 쓰는(인덱스)
  PNG나 GIF는 가져올 때 RGBA로 변환됩니다.
- **애니메이션 GIF**는 **첫 번째 프레임**을 가져옵니다.
- 가져오기는 디스크에서 **읽기 전용**이므로, 파일을 놓아도 원본은 수정되지 않습니다.

> **이미지 크기 제한.** 캔버스 최대 크기(**7680 × 4320**)보다 큰 이미지는 오류 알림과 함께
> **거부됩니다**. 조용히 잘리거나 축소되는 일은 없습니다. 앱 밖에서 먼저 변환하거나 크기를
> 줄이세요.

## `.pixproj` 놓기 → 프로젝트 열기(저장 확인 포함)

**`.pixproj`** 파일을 놓으면 프로젝트로 열립니다.

현재 편집 중인 문서에 **저장되지 않은 변경 사항**이 있으면, 실수로 작업을 잃지 않도록 앱이 먼저
**저장 / 폐기 / 취소** 확인 창을 보여 줍니다.

| 선택 | 결과 |
| --- | --- |
| **저장** | 현재 문서를 저장한 다음, 놓은 프로젝트를 엽니다. |
| **폐기** | 저장하지 않고 놓은 프로젝트를 엽니다. |
| **취소** | 열기를 중단하며, 아무것도 바뀌지 않습니다. |

현재 문서에 저장되지 않은 변경 사항이 **없으면**(또는 열린 문서가 없으면) 확인 창 없이 프로젝트가
바로 열립니다.

## 팔레트 놓기 → 활성 팔레트로 불러오기(실행 취소 가능)

**`.gpl`(GIMP), `.hex`(일반 헥스 목록), `.pal`(JASC-PAL 텍스트)** 팔레트 파일을 놓으면 그 색상이
활성 문서의 팔레트를 **대체합니다**.

- 이 대체는 **실행 취소 가능한 한 단계**이며, **실행 취소**를 한 번 하면 이전 팔레트가 정확히
  복원됩니다.
- 열린 문서가 없으면 놓아도 아무 일도 일어나지 않으며, 짧은 알림만 표시됩니다.

> **어떤 팔레트 형식을 지원하나요?** 지원하는 팔레트는 픽셀 아트에서 흔히 쓰는 **텍스트** 형식인
> `.gpl`, `.hex`, `.pal`입니다. 바이너리 형식인 **`.aco`**(Adobe)와 **`.aseprite`**(Aseprite 자체 형식)는 **아직
> 지원하지 않으며**, 지금은 지원되지 않는 형식으로 알려 줍니다.

## 여러 파일을 한꺼번에 놓기

여러 파일을 한 번에 놓으면 각 파일을 **독립적으로, 형식에 따라, 놓은 순서대로** 처리합니다.

- 이미지 여러 개 → 새 탭 여러 개
- `.pixproj` 파일은 열립니다(저장되지 않은 변경 사항 확인이 적용됩니다)
- 팔레트는 차례로 불러오며, **마지막으로** 놓은 팔레트가 활성 팔레트가 됩니다(각각 실행 취소
  한 단계입니다)

여러 파일 중 알 수 없거나 읽을 수 없는 파일은 알림과 함께 건너뛰며, 나머지는 그대로 처리됩니다.
파일을 하나도 놓지 않으면 아무 일도 일어나지 않습니다.

## 파일을 가져올 수 없을 때

끌어다 놓아서 앱이 비정상 종료되는 일은 없습니다.

- **지원하지 않는 형식**(예: `.txt` 파일, 또는 `.aco`/`.aseprite` 팔레트)은 방해되지 않는 짧은
  상태 알림과 함께 **무시됩니다**.
- **손상되었거나 디코딩할 수 없거나 크기가 너무 큰** 이미지, **잘못된 형식의** 팔레트,
  **올바르지 않은** `.pixproj` 파일은 파일 이름과 문제를 알려 주는 **오류 알림**을 표시하고, 작업
  내용을 **정확히 그대로** 둡니다. 반쯤 만들어진 탭이나 반쯤 불러온 팔레트는 남지 않습니다.

모든 확인 창과 알림은 번역할 수 있고, 키보드로 접근할 수 있으며, 라이트 테마와 다크 테마
모두에서 알아보기 쉽습니다.

## 다루지 않는 내용

- **레이어로 가져오기** — 이미지는 항상 새 문서로 열리며, 현재 문서의 레이어로 열리지 않습니다.
- 팔레트를 쓰는 원본 이미지의 **인덱스 가져오기** — 이미지는 RGBA로 디코딩됩니다. 인덱스 문서가
  필요하면 나중에 **팔레트 ▸ 인덱스로 변환**을 적용하세요([레이어 패널](layers.md) 참고).
- **애니메이션 GIF 가져오기** — 첫 번째 프레임만 가져옵니다.
- 파이프라인의 **내보내기 / 저장** 쪽 — [내보내기와 파이프라인 연동](export-and-pipeline.md)을
  참고하세요.
