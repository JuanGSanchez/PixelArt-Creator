# 클라우드: 저장, 버전, 자동 저장, 복구

**클라우드 계층**을 쓰면 프로젝트가 한 컴퓨터에만 머물지 않고 클라우드에 존재할 수 있습니다.
**클라우드 제공자에 연결**하고, 현재 프로젝트를 클라우드에 **저장**하고, 어느 세션에서든 다시
**열** 수 있습니다. 전체 **버전 내역**을 살펴보며 이전 저장본을 **복원**할 수도 있습니다. 또한
**자동 저장과 비정상 종료 복구**가 있어서, 앱이 비정상적으로 종료되어도 저장하지 않은 작업을
잃지 않습니다.

이 가이드의 모든 기능은 메뉴 막대의 **클라우드** 메뉴에서 실행합니다.

> **제공자에 묶이지 않는 포트 하나.** 앱은 특정 제공자와 직접 통신하지 않습니다. 모든 클라우드
> 작업은 **특정 제공자에 묶이지 않는 하나의 인터페이스**(*클라우드 포트*)를 거칩니다. 연결, 저장,
> 열기, 버전 목록, 복원, 자동 저장/복구 슬롯이 모두 여기에 포함됩니다. 어떤 제공자가 뒷받침하든
> 앱은 **똑같이** 동작하므로 한 제공자에 얽매이지 않으며, 새 제공자는 같은 포트 뒤에 어댑터
> 하나를 더하는 것으로 충분합니다.

이번 릴리스에는 클라우드와 협업 마일스톤 전체가 들어 있습니다. 특정 제공자에 묶이지 않는 포트,
철저히 테스트된 내장 어댑터, `.pixproj` 클라우드 왕복 저장, 버전 내역과 복원, 자동 저장과 비정상
종료 복구가 있습니다. **공유 프로젝트, 댓글, 접속 현황**과 **실시간 공동 편집, 실시간 커서, 아트
브랜칭**도 포함되며, **실제 Google Drive / OneDrive / Dropbox 제공자**도 쓸 수 있습니다. 공유,
댓글, 접속 현황, 실시간, 브랜칭은 [공유 프로젝트, 댓글, 접속 현황, 실시간](collaboration.md)에서
다룹니다.

## 클라우드 제공자 연결

클라우드 동작은 연결하기 전까지 비활성화되어 있습니다.

1. **클라우드** 메뉴를 엽니다.
2. **연결…** 항목을 선택합니다. 이렇게 하면 클라우드 포트를 통해 특정 제공자에 묶이지 않는 연결이
   만들어지고, 클라우드 메뉴의 나머지 항목(**클라우드에 저장**, **클라우드에서 열기**,
   **버전 내역**, **연결 끊기**)이 활성화됩니다.
3. 로그아웃하려면 **클라우드 → 연결 끊기**를 선택합니다. 연결이 해제되고, 다시 연결할 때까지
   클라우드 동작이 비활성화됩니다.

> **자격 증명은 저장소 계층 밖으로 나가지 않습니다.** 실제 제공자 어댑터를 쓰면 로그인 흐름(OAuth)이
> **저장소 계층 안에서만** 진행되고, 앱은 사용자를 위해 시스템 브라우저를 열기만 합니다. 토큰은 UI에
> **절대** 표시되지 않고, `.pixproj` 파일에 **절대** 기록되지 않으며, 로그에도 **절대** 남지
> 않습니다. UI가 알 수 있는 것은 *연결됨 / 연결되지 않음*이라는 단순한 상태뿐입니다.

> **내장 어댑터.** 기본 연결은 내장된 메모리 기반 어댑터입니다. 항상 같은 방식으로 동작하고
> 네트워크도 계정도 필요 없으며, 저장, 버전, 복구로 이어지는 작업 흐름 전체를 처음부터 끝까지
> 쓸 수 있도록 존재합니다. 실제 온라인 제공자를 쓰려면 아래 *실제 클라우드 제공자 연결*을
> 참조하세요.

## 실제 클라우드 제공자 연결

**같은** 연결 흐름 뒤에서 **실제** Google Drive, OneDrive, Dropbox 계정을 연결할 수 있습니다.
그래서 이 가이드의 모든 단계(저장, 열기, 버전 내역, 자동 저장/복구)가 온라인 저장소 위에서도
똑같이 작동합니다.

> **자격 증명이 필요한 기능.** 실제 제공자는 **자격 증명이 있어야 쓸 수 있습니다**. 선택한 서비스의
> OAuth **클라이언트 ID**와 실제 네트워크 연결이 필요하므로, 기본으로 켜져 있지 않고 의도적으로
> 구성해야 합니다. 위의 내장 어댑터에는 이런 것이 필요 없습니다.

### 로그인 방식

1. **클라우드 → 연결…** 항목을 선택하고, 구성해 둔 실제 제공자를 고릅니다.
2. 앱이 **시스템 브라우저**에서 제공자의 로그인/동의 페이지를 엽니다. PixelArt Creator는
   표준 데스크톱 방식인 **OAuth 인증 코드 + PKCE** 흐름을 사용하며, 리디렉션은
   **루프백 주소**로 받습니다. **내장 웹 뷰는 없고** 앱에 저장되는 **클라이언트 시크릿도 없습니다**.
3. 브라우저에서 접근을 승인합니다. 브라우저가 앱으로 다시 리디렉션하면 앱이 연결을 마무리합니다.
   클라우드 메뉴의 저장/열기/버전 동작은 내장 어댑터일 때와 똑같이 활성화됩니다.
4. 로그아웃하려면 **클라우드 → 연결 끊기**를 선택합니다.

> **자격 증명은 저장소 계층 밖으로 나가지 않습니다.** 로그인 전체가 **저장소 계층 안에서만**
> 진행됩니다. **갱신 토큰은 OS 키링에 저장되며**(제공자별 키), 수명이 짧은 액세스 토큰은 메모리에만
> 보관되고 자동으로 갱신됩니다. 토큰은 UI에 표시되거나 `.pixproj` 파일에 기록되거나 로그에 남는
> 일이 **절대** 없습니다.

> **제공자가 달라도 똑같이 동작합니다.** 모든 제공자가 하나의 클라우드 포트 뒤에 있으므로, 내장
> 어댑터에서 Drive / OneDrive / Dropbox로 바꾸거나 그 사이에서 옮겨 가도 저장, 버전 탐색, 작업
> 복구 방식은 **전혀** 달라지지 않습니다.

## 프로젝트를 클라우드에 저장하기

1. 프로젝트가 열려 있고 제공자가 연결된 상태에서 **클라우드 → 클라우드에 저장…** 항목을
   선택합니다.
2. 입력 창이 나타나면 **클라우드 프로젝트 이름**을 입력합니다. 이 이름으로 클라우드의 프로젝트가
   구분되므로, 같은 프로젝트에 계속 버전을 추가하려면 같은 이름을 다시 쓰세요.
3. 앱이 프로젝트를 `.pixproj`로 직렬화해 **새 버전**으로 저장합니다. 끝나면 상태 표시줄에
   *"클라우드에 저장했습니다."* 메시지가 나타납니다.

저장할 때마다 `.pixproj` 전체가 전송되며, 저장 형식은 로컬 파일과 **같습니다**. 이 형식은
검증되며 형식 버전 번호가 붙어 있습니다. 클라우드 계층은 자체 형식을 따로 두지 않고, `.pixproj`를 원자적
*동기화 단위*로 실어 나를 뿐입니다.

> **저장해도 앱이 멈추지 않습니다.** 직렬화와 업로드는 **GUI 스레드 밖에서** 실행되므로, 대형(최대
> 8K) 프로젝트에서도 창이 계속 반응합니다. 저장이 끝나기를 기다리는 동안에도 작업을 계속할 수
> 있습니다.

> **저장할 때마다 새 버전이 됩니다.** 저장해도 이전 클라우드 저장본을 **덮어쓰지 않고** 버전
> 내역에 항목을 추가합니다. 내역은 프로젝트당 가장 최근 **100**개 버전까지만 유지됩니다.

## 클라우드에서 프로젝트 열기

1. **클라우드 → 클라우드에서 열기…** 항목을 선택합니다.
2. 열려는 **클라우드 프로젝트 이름**을 입력합니다.
3. 앱이 프로젝트의 최신 버전을 가져와 **새 탭**에서 엽니다.

지금 작업 중인 내용은 바뀌거나 방해받지 않습니다. 클라우드 프로젝트는 별도의 탭으로 들어옵니다.

> **클라우드 파일은 신뢰할 수 없는 파일로 취급됩니다.** 클라우드에서 가져온 `.pixproj` 파일은 로컬
> 파일과 똑같이 방어적으로 검증됩니다. 모든 필드의 형식과 범위를 검사하고 페이로드 크기를
> 제한하며, 형식이 잘못되었거나 크기가 너무 크거나 알 수 없는 버전인 파일은 **명확한 오류**와 함께
> 거부됩니다. 앱이 비정상 종료되는 일은 없고, 파일 안의 코드를 실행하는 일도 **절대** 없습니다.
> 가져온 프로젝트를 검증할 수 없으면 경고 대화 상자가 나타나고 현재 작업은 그대로 유지됩니다.

## 버전 내역 탐색과 버전 복원

저장할 때마다 순서가 있는 새 버전이 만들어지며, 그중 어느 것으로든 되돌아갈 수 있습니다.

1. **클라우드 → 버전 내역…** 항목을 선택합니다(이번 세션에서 클라우드 프로젝트를 열거나 저장한
   적이 없으면 먼저 클라우드 프로젝트 이름을 묻습니다).
2. **클라우드 버전 내역** 대화 상자가 저장된 모든 버전을 오래된 것부터 최신 순으로 다음 열과 함께
   나열합니다.
    - **버전** — 버전의 순번 또는 식별자.
    - **마커** — 버전의 순서를 나타내는 마커.
    - **크기(바이트)** — 저장된 `.pixproj` 파일의 크기.
    - **고정됨** — 버전이 고정(보관)되어 있는지 여부로, *예* / *아니요*.
    - **상위** — 이 저장본의 바로 앞 버전.
3. 버전을 선택하면 목록 아래 미리 보기 영역에 상세 정보가 표시됩니다.
4. **복원**을 눌러(또는 행을 두 번 누르거나 **Enter** 키를 눌러) 그 버전을 불러옵니다.

> **복원은 안전합니다. 새 탭으로 열립니다.** 이전 버전을 복원하면 그 버전을 가져와 검증한 뒤
> **새 탭**에서 엽니다. 현재 작업이나 가장 최근 클라우드 저장본을 **덮어쓰지 않으며**, 복원된
> 사본을 어떻게 할지는 사용자가 정합니다.

버전 목록은 대화 상자가 열리기 전에 GUI 스레드 밖에서 가져오므로, 내역을 탐색해도 앱이 멈추지
않습니다.

## 자동 저장과 비정상 종료 복구

연결된 프로젝트에서 작업하는 동안 앱은 작업 사본을 전용 **복구 슬롯**에 백그라운드로
**자동 저장**합니다.

- 자동 저장은 정해진 주기(기본 **2분마다**)로 동작하며, **문서에 저장하지 않은 변경 사항이 있을
  때만** 실행됩니다. 변경 사항이 없는 문서는 자동 저장되지 않습니다.
- 복구 슬롯은 **버전 내역과 별개**입니다. 자동 저장은 눈에 보이는 버전을 만들지 않으며,
  **마지막으로 직접 클라우드에 저장한 내용을 덮어쓰지도 않습니다**.
- 자동 저장은 GUI 스레드 밖에서 실행되므로 그리기를 방해하지 않습니다.

### 다시 시작할 때 나타나는 복구 확인 창

저장하지 않은 작업이 있는 상태에서 앱이 비정상적으로 종료되었다면(오류로 인한 종료나 정전),
다음에 앱을 시작하고 **연결하는 순간** 남아 있는 복구 슬롯을 감지합니다. 이때 **저장하지 않은 작업
복구** 확인 창이 나타납니다.

- **복구** — 자동 저장된 사본을 가져와 검증한 뒤 **새 탭**에서 엽니다. 마지막으로 직접 저장한
  내용에는 영향이 없습니다.
- **폐기** — 확인 창을 닫고 모든 것을 그대로 둡니다.

> **복구도 방어적으로 디코딩됩니다.** 복구된 사본도 다른 클라우드 파일과 똑같은 신뢰할 수 없는 입력
> 검증을 거치므로, 복구 슬롯이 손상되어도 시작할 때 앱이 비정상 종료되는 일은 없습니다. 최악의
> 경우에도 명확한 오류가 표시될 뿐이며 계속 작업할 수 있습니다.

> **자동 저장에는 연결된 제공자가 필요합니다.** 자동 저장과 재시작 시의 복구 확인 창은 클라우드
> 포트를 통해 작동하므로 **연결되어 있는 동안에만** 활성화됩니다. 안전망이 계속 작동하게 하려면
> 세션을 시작할 때 제공자를 연결하세요.

## 클라우드와 협업 마일스톤의 나머지

이 페이지는 단독 사용자의 클라우드 작업, 즉 저장, 버전, 자동 저장/복구와 실제 제공자 연결을
다룹니다. 그 위에 구축되는 협업 기능은 모두 [공유 프로젝트, 댓글, 접속 현황, 실시간](collaboration.md)에
설명되어 있습니다. 여기에는 **공유 프로젝트와 멤버십**, **댓글**, **접속 현황**, **항상 같은 결과로 수렴하는 방식**,
**실시간 공동 편집과 실시간 커서**, **아트 브랜칭**이 포함됩니다.
