# 자동화, 매크로, 스크립팅, 플러그인

**자동화 시스템**으로 편집기 자체의 작업을 기록하고, 스크립트로 짜고, 재생하고, 일괄 처리할 수
있습니다. 콘텐츠를 절차적으로 생성할 수도 있고, 신뢰할 수 있는 플러그인으로 앱을 확장할 수도
있습니다. 이 모든 기능은 GUI와 GUI 없는 `pixelart-run` 명령줄이 함께 쓰는 **하나의** 엔진을 거치므로,
패널에서 실행하든 빌드 스크립트에서 실행하든 자동화는 **똑같이** 동작합니다.

> **설계 단계부터 안전하게 — `eval`은 어디에도 없습니다.** 스크립팅은 임의의 Python이 아니라 **범위가
> 정해진 데이터 기반 명령 DSL**입니다. 자동화는 언어가 아니라 *검증된 작업 목록*이며, 각 작업은
> `{name, params, seed}` 형태입니다. 이 경로 어디에도 사용자 입력에 대한 **`eval` / `exec` / `compile` / `__import__` 호출이
> 없습니다**. 빠져나갈 인터프리터 자체가 없습니다. 신뢰할 수 있는 단일 디스패처가 각 작업의 이름을
> **허용 목록**과, 매개변수를 선언된 스키마와 대조한 다음에야 그에 대응하는 되돌릴 수 있는 명령을
> 만듭니다.

## 매크로 — 기록, 재생, `.pixmacro` 형식

**매크로** 패널은 사용자가 수행한 작업을 기록해 두었다가 나중에 재생합니다.

- **매크로 기록**은 각 단계의 *입력*, 즉 확정된 매개변수와 무작위 단계의 **시드**를 캡처하며, 픽셀
  차이는 저장하지 않습니다. 기록한 내용이 곧 재생할 때 다시 실행되는 내용입니다.
- **재생**은 기록된 작업을 현재 문서에 **실행 취소 한 단계**로 다시 적용하므로, 실행 취소 한 번이면
  매크로 전체가 한꺼번에 취소됩니다.

매크로는 **`.pixmacro`** 파일로 저장됩니다. 맨 위에 형식과 버전 정보 필드를 둔 평범한 JSON입니다.

```
{
  "format": "pixmacro",
  "schema_version": "1",
  "min_app_version": "0.8.0",
  "api_version": "1",
  "ops": [
    { "op": "batch_recolour", "params": { }, "seed": null },
    { "op": "procgen",        "params": { }, "seed": 12345 }
  ]
}
```

- **`schema_version` / `api_version` / `min_app_version`** 필드는 불러올 때 검사됩니다. 알 수 없거나
  지원하지 않는 버전이면 매크로를 잘못 재생하는 대신 명확한 오류와 함께 **분명하게 실패합니다**.
- **`params`** 값은 JSON 기본 타입으로만 이루어져 있어, 매크로를 저장했다가 불러오면 **똑같은**
  매크로가 됩니다. 색상과 인덱스 맵은 목록으로 담깁니다.
- **`seed`** 값은 무작위 단계마다 기록되므로 재생을 재현할 수 있습니다.

> **재현 가능한 재생.** 같은 시작 문서에서 같은 매크로를 두 번 재생하면 **상태가 똑같은** 문서가
> 나옵니다. 무작위 단계는 기록된 시드에서만 값을 뽑으며, 시스템 시계, 시드 없는 난수, 로캘에 따른
> 차이도 없습니다. 그래서 매크로를 빌드 파이프라인에서 안심하고 실행할 수 있습니다.

`.pixmacro` 파일을 불러오는 과정은 **방어적**입니다. 모든 필드의 타입, 범위, 버전을 검사하고, 형식이
잘못되었거나 범위를 벗어난 문서는 명확한 오류를 내며, 그 내용을 `eval`/`exec`에 넘기는 일은
**없습니다**.

## 스크립트 실행

**스크립트 실행기**는 매크로 재생과 같은 신뢰할 수 있는 디스패처를 통해 작업 목록을 처리합니다.
스크립트 실행은 **원자적**입니다.

1. **모든 작업을 먼저 검증합니다.** 아무것도 적용하기 **전에** 모든 작업 이름을 허용 목록과, 모든
   매개변수를 스키마와 대조합니다.
2. 실행 전체가 **하나로 묶인 되돌릴 수 있는 명령**으로 적용됩니다.
3. 도중에 작업 하나가 실패하면 이미 적용된 작업이 **역순으로 롤백**되므로, 여러 작업으로 된 실행이
   실패해도 문서는 **그대로**이며 절반만 적용된 상태가 되는 일은 없습니다.

실행 전체가 묶인 명령 하나이므로, 완료된 스크립트는 **실행 취소 한 단계**입니다.

## 플러그인 — 관리자, 동의, 신뢰 모델

**플러그인** 패널은 플러그인을 찾아서 사용하거나 사용 안 함으로 바꿉니다. 플러그인은 새 DSL 작업을
등록하는 방식으로만 편집기를 확장합니다.

- **플러그인을 찾아내기만 해서는 아무것도 실행되지 않습니다.** 설치된 플러그인은 (표준 Python 엔트리 포인트를 통해)
  *발견*되지만, 설치되어 있다는 이유만으로 **무언가가 불러와지거나 실행되지는 않습니다**. 목록에
  표시될 뿐이며, 사용자가 직접 조작하기 전에는 아무 동작도 하지 않습니다.
- **기본은 거부, 허용은 명시적 동의로.** 플러그인을 사용 설정하면 **DSL 명령 레지스트리만을 접근
  범위로 갖는 권한 객체**가 전달됩니다. 플러그인은 `eval`/`exec` 호출을 할 수 없고, UI에 접근할 수
  없으며, 사용자가 허락한 권한 밖에서는 파일 시스템이나 네트워크에 손댈 수 없습니다. **선언하지
  않았거나 사용자가 허락하지 않은 권한은 모두 거부됩니다.** 플러그인이 추가한 작업은 그 플러그인
  이름 아래 네임스페이스로 묶이므로, 플러그인이 내장 작업을 가릴 수 없습니다.
- **사용 안 함도 깔끔합니다.** 플러그인을 사용 안 함으로 바꾸면 그 플러그인이 추가한 작업의 등록이
  해제됩니다.

> **이번 릴리스는 신뢰와 동의를 전제로 합니다.** Python 플러그인을 *불러오는* 것 자체가 코드를
> 실행하는 일이므로, 프로세스 내부의 권한 모델은 강제력이 약한 **권고 수준**입니다. **직접 설치하고 동의한
> 신뢰할 수 있는 확장**에는 충분하지만, 신뢰할 수 없는 마켓플레이스의 임의 코드에는 맞지 않습니다.
> 신뢰하는 플러그인만 설치하세요.

## 일괄 색상 변경

**일괄 색상 변경**은 하나의 색상 매핑을 **여러 대상에 한꺼번에** 적용하며, 이는 **트랜잭션으로
처리되는, 되돌릴 수 있는 명령 하나**입니다.

- **인덱스** 대상은 팔레트 인덱스(`old_index → new_index`)를, **RGBA** 대상은 색상
  (`old_rgba → new_rgba`)을 바꿉니다. 편집기의 기존 색상 변경 기능을 그대로 쓰므로, 일괄 처리된
  대상은 같은 매핑으로 그 대상만 따로 색상을 바꾼 결과와 **바이트까지 일치**합니다.
- 이 작업은 **트랜잭션**입니다. 모든 대상을 검증하고 대상별 단계를 만든 **다음에야** 적용합니다.
  잘못된 대상이 있으면 그 대상의 이름을 밝히며 실패하고 **아무것도 바뀌지 않습니다**. 일괄 처리
  전체가 **실행 취소 한 단계**입니다.

## 절차적 생성

**절차적 생성** 패널은 영역을 생성된 콘텐츠로 채웁니다. 자체 제작한 **시드 기반** 생성기 다섯 가지를
쓸 수 있습니다.

| 생성기 | 만들어 내는 것 |
| --- | --- |
| **값 노이즈** | 시드 기반 값 격자 노이즈. |
| **그라데이션 노이즈** | Perlin 방식 그라데이션 노이즈. |
| **OpenSimplex 노이즈** | 특허 문제가 없는 simplex 격자 기반 그라데이션 노이즈. |
| **셀룰러 오토마타** | 셀룰러 오토마타 패턴. |
| **디더링 그라데이션** | 문서 팔레트에 디더링으로 입힌 부드러운 두 색 그라데이션으로, 결과가 팔레트 안에 머뭅니다. |

모든 생성기는 매개변수와 시드만으로 결과가 정해지는 **순수 함수**입니다. 시드와 매개변수가 같으면
출력도 언제나 같습니다. 생성된 콘텐츠는 **되돌릴 수 있는 명령 경로**로 기록되므로 어떤 생성이든
실행 취소 한 단계입니다. 출력은 축마다 플랫폼의 절차적 생성 크기 상한으로 제한됩니다.

## 실행 취소와 응답성

모든 자동화(매크로 재생, 스크립트 실행, 일괄 색상 변경, 절차적 채우기)는 **일반 실행 취소 스택에
한 단계로** 쌓이므로 언제든 취소할 수 있습니다. GUI에서는 자동화가 항상 같은 순서로 종료되는 **백그라운드
작업 스레드**에서 실행되어, 긴 일괄 처리나 큰 절차적 채우기에도 창이 멈추지 않습니다.

## `pixelart-run` 명령줄

자동화와 CI를 위해 `pixelart-run`은 `.pixproj` 프로젝트에 `.pixmacro` 매크로를 GUI **없이** 재생합니다. GUI가
쓰는 것과 **동일한** 신뢰할 수 있는 디스패처를 거치므로, 결과 문서는 같은 입력에 같은 자동화를 GUI로
실행했을 때와 **상태가 똑같습니다**.

```
pixelart-run --input PROJECT.pixproj --macro MACRO.pixmacro --output OUT.pixproj [options]
```

| 옵션 | 의미 |
| --- | --- |
| `--input PATH` | **(필수)** 매크로를 실행할 원본 `.pixproj` 프로젝트. |
| `--macro PATH` | **(필수)** 재생할 `.pixmacro` 매크로. |
| `--output PATH` | **(필수)** 결과를 쓸 `.pixproj` 경로. |
| `--seed N` | 시드가 기록되지 않은 작업의 시드를 덮어씁니다(기록된 시드가 항상 우선). |
| `--param KEY=VALUE` | 매크로 매개변수를 주입하거나 덮어쓰며, 여러 번 쓸 수 있습니다. |

**종료 코드:** `0` 성공, `1` 자동화 실패(스크립트 / 매크로 / 플러그인 / 일괄 처리 / 절차적 생성 오류
또는 쓰기 실패), `2` 잘못된 인수, 또는 형식이 잘못되었거나 읽을 수 없는 입력 프로젝트나 매크로.

> **콘솔 엔트리 포인트.** `pixelart-run`은 `pip install` 때 콘솔 스크립트로 설치됩니다.

## 다루지 않는 내용

- **임의의 Python 스크립팅**은 **설계상 지원하지 않습니다.** 스크립팅은 허용 목록에 있는 제한된 명령
  DSL이며 범용 인터프리터가 아닙니다. 이는 의도한 보안 경계이며, 언젠가 풀어야 할 제약이 아닙니다.
- **신뢰할 수 없는 서드파티 플러그인의 격리**는 **보류** 중입니다. 이번 릴리스에서 플러그인은 신뢰와
  동의를 전제로 하므로, 신뢰하는 플러그인만 설치하세요.
