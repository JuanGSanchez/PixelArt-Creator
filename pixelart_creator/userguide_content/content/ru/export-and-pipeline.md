# Экспорт и интеграция с конвейером

**Система экспорта** превращает проект в ресурсы, которые использует игровой конвейер: один
**PNG**, **анимированный GIF**, **спрайт-лист** или упакованный **атлас текстур**, каждый с
необязательными метаданными в формате **JSON в стиле Aseprite** и готовыми к переносу в проект
**предустановками для движков** — **Unity** и **Godot**. Вы можете экспортировать одну цель из
диалога экспорта, поставить в очередь несколько целей на панели пакетного экспорта или запустить
всё это без графического интерфейса из командной строки `pixelart-export` — и любым из этих
путей получатся **одни и те же байты**. Диалог экспорта открывается через **Файл ▸ Экспорт…**
или сочетанием **Ctrl+Shift+E**.

> **Побайтно воспроизводимый экспорт.** Экспорт **детерминирован**: для одного и того же
> входного документа и тех же параметров выходные байты каждый раз одинаковы — кадры
> перебираются в явно заданном порядке, GIF использует фиксированную общую палитру с
> выключенным дизерингом, а кодировщики зафиксированы. Графический интерфейс и
> командная строка используют **один и тот же** движок, поэтому экспорт одного и того же
> документа из интерфейса и из командной строки **побайтно идентичен**. Гарантия действует
> *в одной и той же среде* (с зафиксированным набором инструментов) и не распространяется на
> разные компьютеры.

| Сочетание | Действие |
| --- | --- |
| **Ctrl+Shift+E** | Открыть диалог экспорта. |

## Растровый экспорт (PNG / GIF)

- **PNG** экспортирует **кадр 0** как одно изображение RGBA — цель для статичного изображения.
- **GIF** экспортирует анимацию: все кадры по порядку, каждый показывается в течение своей
  **длительности кадра** (длительности задаются на [временной шкале анимации](animation-timeline.md)),
  а число повторов, способ удаления кадра (frame disposal) и прозрачность записываются в файл.
  У всех кадров **одна фиксированная палитра** (сокращение числа цветов методом медианного
  сечения по всей анимации), а дизеринг **выключен**, благодаря чему GIF получается
  побайтно воспроизводимым.

> **Число повторов GIF.** Флаг `--loop` (командная строка) и поле **Число повторов** (диалог)
> задают, сколько раз повторяется GIF; **`0` означает бесконечный повтор**.

## Спрайт-листы и атласы текстур

- **Спрайт-лист** раскладывает каждый кадр по **равномерной сетке** построчно: кадр `k`
  находится в столбце `k % columns` и строке `k // columns`, с настраиваемым **отступом** между
  спрайтами и без внешнего поля. Чтобы управлять формой листа, задайте число столбцов.
- **Атлас текстур** плотно упаковывает кадры общим упаковщиком **MaxRects** (поворот выключен,
  поэтому спрайты всегда выровнены по осям). Атлас — вариант, экономящий место, когда кадры
  различаются по содержимому.

> **Предельный размер атласа.** Размер атласа ограничен платформенным пределом **8K**. Если
> набор спрайтов не помещается в этот предел, экспорт **корректно завершается ошибкой** — с
> понятным сообщением об ошибке атласа (а не молчаливым наложением, усечением или аварийным
> завершением): уменьшите отступ, размер кадра или число кадров и повторите попытку.

## Метаданные JSON

Экспорт спрайт-листа и атласа может создавать **сопроводительный файл с метаданными JSON** в
формате **Aseprite *Array***: массив `frames[]` (прямоугольник, исходный размер и длительность
каждого кадра) и блок `meta{}`, содержащий **теги** кадров и длительности отдельных кадров.
JSON **детерминирован** — ключи отсортированы, разделители фиксированы, а координаты
целочисленные, — поэтому он читается обратно без потерь, а при сравнении (diff) видны только
настоящие различия. Включайте и отключайте его флажком **Записать метаданные JSON** в диалоге или флагами
`--json` / `--no-json` в командной строке (по умолчанию включено).

## Предустановки для движков (Unity / Godot)

Наряду с изображением и JSON экспорт может записать **готовую для движка предустановку**, чтобы
ресурс можно было сразу перенести в проект:

| Предустановка | Что записывает |
| --- | --- |
| **Unity** | Сопроводительный файл `.meta` спрайта: режим спрайта **Multiple**, `pixelsPerUnit`, точка опоры (pivot) и `filterMode = Point` (чёткие пиксели, без билинейного сглаживания). |
| **Godot** | Ресурс `SpriteFrames` `.tres` (Godot 4.2), собранный из экспортированных кадров. |

Выберите предустановку в диалоге или передайте `--preset unity` / `--preset godot` в командной
строке (`--preset none` — значение по умолчанию — не записывает предустановку). Файлы
предустановок строятся детерминированно из тех же метаданных раскладки, что и изображение.

## Пакетный экспорт

Панель **Пакетный экспорт** ставит в очередь **несколько целей одновременно** — например, PNG,
GIF и атлас для Unity из одного проекта за один запуск. Пакетный экспорт **продолжает работу
при сбое**: если одна цель завершается сбоем (скажем, атлас не помещается), остальные цели всё
равно экспортируются, а о сбое сообщается только для этой цели, поэтому одна неудачная цель
никогда не прерывает весь пакет. Кнопка **Экспортировать всё** экспортирует документ активной
вкладки во все цели из очереди за один запуск.

## Регистрация результата экспорта в библиотеке

В диалоге экспорта есть флажок **Также добавить в библиотеку ресурсов**, который регистрирует
результат экспорта в [библиотеке ресурсов](asset-library.md) тем же действием, что и
экспорт, — это включается явно, а не по умолчанию. Если флажок установлен, после успешного
экспорта открывается общий диалог **Зарегистрировать ресурс** (название, тип, теги); если он
снят, экспорт проходит, вообще не затрагивая библиотеку, точно так же, как до появления этой
возможности.

## Отзывчивость

Вся работа экспорта выполняется **вне потока интерфейса** в фоновом рабочем потоке, под
**индикатором хода выполнения, который можно отменить**, — поэтому экспорт большой анимации или
атласа никогда не замораживает окно. Экспорт **только читает** ваш документ: он никогда не
изменяет его и не добавляет в стек отмены ни одного шага.

> **Отмена одной большой цели.** Отмена вступает в силу между целями сразу; отмена **посреди
> кодирования одной большой цели** менее точна: текущее кодирование доводится до конца, и лишь
> затем учитывается отмена.

## Командная строка `pixelart-export`

Для автоматизации и CI `pixelart-export` запускает **тот же самый** путь экспорта без
графического интерфейса — его результат побайтно идентичен результату экспорта того же
документа с теми же параметрами через графический интерфейс. Файл `.pixproj` он загружает через
тот же загрузчик проектов с проверкой входных данных, который использует приложение.

```
pixelart-export --input PROJECT.pixproj --format FORMAT --output OUT [options]
```

| Флаг | Значение |
| --- | --- |
| `--input PATH` | **(обязательно)** исходный проект `.pixproj` для экспорта. |
| `--format FORMAT` | **(обязательно)** одно из значений `png`, `gif`, `sprite-sheet`, `atlas`. |
| `--output PATH` | **(обязательно)** путь выходного изображения. |
| `--preset PRESET` | предустановка для движка: `none` (по умолчанию), `unity`, `godot`. |
| `--columns N` | число столбцов спрайт-листа. |
| `--padding N` | отступ между спрайтами, в пикселях. |
| `--loop N` | число повторов GIF (`0` = бесконечно). |
| `--tag NAME` | экспортировать только диапазон кадров с указанным тегом (по умолчанию — весь документ). |
| `--json` / `--no-json` | создавать сопроводительный файл JSON для спрайт-листа или атласа (по умолчанию включено). |

**Коды завершения:** `0` — успех; `1` — ошибка экспорта / упаковки / записи (например, атлас
не помещается или сбой записи в файловую систему); `2` — неверные аргументы либо некорректный /
нечитаемый входной проект.

> **Тот же путь, что и в графическом интерфейсе.** Поскольку командная строка и диалог вызывают
> один и тот же движок, вы можете подобрать экспорт интерактивно, а затем в точности
> воспроизвести его в скрипте сборки, передав те же параметры в виде флагов.

## Что не охвачено

- **APNG** (анимированный PNG) — **отложен**; в этом выпуске экспортируются статичный PNG
  (кадр 0) и анимированный GIF.
- **Побайтная идентичность между разными компьютерами** — гарантия побайтной воспроизводимости
  действует *в одной и той же среде* (с зафиксированным набором инструментов); набор
  инструментов на другом компьютере может дать другие байты.
- **Точная отмена посреди кодирования** одной большой цели — отмена учитывается между целями, а
  не на середине кодирования одной цели.
