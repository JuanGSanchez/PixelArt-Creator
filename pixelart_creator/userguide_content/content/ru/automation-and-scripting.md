# Автоматизация, макросы, скрипты и плагины

**Система автоматизации** позволяет записывать, программировать скриптами, воспроизводить и
пакетно применять собственные операции редактора, а также процедурно генерировать содержимое.
Всё это работает через **один** движок, общий для графического интерфейса и для командной
строки `pixelart-run` (запуск без интерфейса), поэтому автоматизация выполняется **одинаково**,
запускаете ли вы её из панели или из скрипта сборки.

> **Безопасность заложена в конструкцию: никакого `eval`, никогда.** Скрипты — это
> **ограниченный, управляемый данными командный DSL**, а не произвольный Python. Автоматизация —
> это *проверенный список операций* (`{name, params, seed}`), но никогда не язык: на этом пути
> **нигде нет `eval` / `exec` / `compile` / `__import__` для ваших входных данных** —
> интерпретатора, из которого можно было бы вырваться, просто нет. Единый доверенный
> диспетчер сверяет имя каждой операции с **белым списком**, а её параметры — с объявленной
> схемой, прежде чем построить обратимую команду, которой она соответствует.

## Макросы: запись, воспроизведение и формат `.pixmacro`

Панель **Макросы** записывает выполняемые вами операции и позже воспроизводит их:

- Кнопка **Записать макрос** фиксирует *входные данные* каждого шага — итоговые параметры и,
  для любого случайного шага, **начальное значение** — а не разницу в пикселях.
  Повторно выполняется ровно то, что вы записали.
- Кнопка **Воспроизвести** повторно применяет записанные операции к текущему документу как
  **один шаг отмены**, поэтому отмена откатывает весь макрос сразу.

Макрос хранится в файле **`.pixmacro`** — это обычный JSON с оболочкой, в которой указаны
версии:

```
{
  "format": "pixmacro",
  "schema_version": "1",
  "min_app_version": "0.8.0",
  "api_version": "1",
  "ops": [
    { "op": "batch_recolour", "params": { }, "seed": null },
    { "op": "procgen",        "params": { }, "seed": 12345 }
  ]
}
```

- Значения **`schema_version` / `api_version` / `min_app_version`** проверяются при загрузке:
  неизвестная или неподдерживаемая версия **приводит к явной ошибке** с понятным сообщением, а
  не к неверному воспроизведению.
- Значения **`params`** изначально представлены в JSON, поэтому сохранение и последующая
  загрузка макроса дают **идентичный** макрос — цвета и карты индексов передаются списками.
- Значение **`seed`** записывается для каждого стохастического шага, чтобы воспроизведение
  давало один и тот же результат.

> **Детерминированное воспроизведение.** Двукратное воспроизведение одного и того же макроса
> на одном и том же исходном документе даёт **идентичный по состоянию** документ. Каждый
> случайный шаг берёт значения только из своего записанного начального значения — без
> системных часов, без случайности, не привязанной к начальному значению, без зависимости от
> локали. Именно это делает макрос безопасным для запуска в конвейере сборки.

Загрузка `.pixmacro` выполняется **с проверкой входных данных**: каждое поле проверяется по
типу, границам и версии, некорректный документ или документ со значениями вне допустимых
границ вызывает понятную ошибку, а содержимое **никогда** не передаётся в `eval`/`exec`.

## Запуск скриптов

Панель **Запуск скриптов** передаёт список операций через тот же доверенный диспетчер, которым
пользуется воспроизведение макроса. Запуск скрипта **атомарен**:

1. **Каждая операция проверяется заранее** — все имена операций сверяются с белым списком, а все
   параметры — со своей схемой, **прежде чем что-либо будет применено**.
2. Весь запуск применяется как **одна сгруппированная обратимая команда**.
3. Если какая-либо операция даёт сбой на полпути, уже применённые операции **откатываются в
   обратном порядке**, поэтому неудавшийся запуск из нескольких операций оставляет документ
   **без изменений** — а не применённым наполовину.

Поскольку запуск — это одна сгруппированная команда, завершённый скрипт — **один шаг отмены**.

## Плагины: менеджер, согласие и модель доверия

Панель **Плагины** перечисляет плагины, показывает разрешения каждого плагина, манифест которого
вы загрузили, а также включает и отключает их. Плагин предназначен для расширения редактора
путём регистрации новых операций DSL. **В этом выпуске приложение не загружает и не
запускает код плагина:** обнаружение плагина, загрузка манифеста, включение и отключение
никогда не вызывают плагин. Разрешения, заявленные в манифесте, описывают предполагаемое
использование плагина; они не ограничивают того, что способен делать собственный код плагина
(см. примечание ниже).

- **Обнаружение лишь перечисляет плагины.** Приложение находит установленные плагины через
  стандартные точки входа Python, но читает только их имена и версии: оно **не загружает и не
  запускает** их код. У обнаруженного плагина разрешения не показываются, и включить его
  невозможно, потому что приложение не читает разрешения из самого плагина. Разрешения берутся
  из файла манифеста, который вы добавляете в панель с диска и который появляется в списке
  отдельной записью. Приложение не проверяет, относится ли манифест к установленному вами
  плагину.
- **Согласие распространяется на манифест, а не на код плагина.** Кнопка **Включить**
  показывает разрешения, заявленные в манифесте, и просит вас подтвердить их. Вы одобряете их
  целиком либо не включаете плагин. Приложение не сверяет манифест с тем, что на самом деле
  делает код плагина. Включение запоминает одобренные вами разрешения (только в памяти) и
  отмечает плагин как включённый; код плагина оно не запускает: приложение нигде этого
  не делает. Ваше согласие не сохраняется: при закрытии редактора
  каждый плагин снова отключается. Хост плагинов устроен так: если бы вызывающая сторона
  передала ему код, который нужно выполнить при включении плагина, этот код получил бы объект
  разрешений, и вызов через этот объект без выданного на него разрешения был бы отклонён; в
  этом выпуске ничто не передаёт хосту такого кода. Операции, зарегистрированные через этот
  объект, получают в качестве префикса имя плагина, поэтому их имя не может совпасть с именем
  встроенной операции, а разрешение на чтение через этот объект возвращает сам переданный
  документ, а не его копию. Код, который не проходит через этот объект, им не ограничен: он может напрямую
  регистрировать или удалять операции, в том числе встроенные.
- **Отключение убирает операции, а не код плагина.** Кнопка **Отключить** снимает с регистрации
  операции, которые были зарегистрированы через объект разрешений; в этом выпуске таких
  операций нет, потому что ничто их не регистрирует. Отключение не отменяет ничего из того, что
  собственный код плагина уже успел сделать.

> **У плагинов нет песочницы.** Плагин не изолирован от вашего компьютера, и в этом
> выпуске приложение не обеспечивает изоляции ни для одного плагина. Установка плагина
> помещает на ваш компьютер чужой код на Python, а приложение не выполняет установку и не
> проверяет её. Python-пакет также может попросить Python выполнять код при каждом запуске
> Python в среде, где этот пакет установлен; в такую среду входит и редактор. Поэтому для
> запуска кода плагина может быть достаточно его установки, даже если вы ни разу не открывали
> панель **Плагины**.
> Код, который выполняется в собственном процессе редактора, как бы он туда ни попал, имеет
> такой же доступ к вашим файлам и сети, как и сам редактор, какие бы разрешения ни заявлял
> плагин. Устанавливайте и включайте только те плагины, которым вы доверяете.

## Пакетная перекраска

**Пакетная перекраска** применяет одно сопоставление цветов сразу ко **многим целям** как
**единую транзакционную обратимую команду**:

- Для **индексированных** целей переназначаются индексы палитры (`old_index → new_index`), для
  целей **RGBA** — цвета (`old_rgba → new_rgba`). Используются уже существующие операции
  перекраски редактора, поэтому цель, обработанная в пакете, **побайтно идентична** той же цели,
  перекрашенной отдельно с тем же сопоставлением.
- Она **транзакционна**: каждая цель проверяется, и её собственный шаг строится **до того, как
  что-либо будет применено**. Недопустимая цель приводит к ошибке с названием этой цели, при
  этом **ничего не изменяется**. Весь пакет — **один шаг отмены**.

## Процедурная генерация

Панель **Процедурная генерация** заполняет область сгенерированным содержимым. Доступны пять
собственных генераторов, **использующих начальное значение**:

| Генератор | Что создаёт |
| --- | --- |
| **Шум значений** | Шум на сетке значений с начальным значением. |
| **Градиентный шум** | Градиентный шум в стиле Перлина. |
| **Шум OpenSimplex** | Градиентный шум на симплексной сетке, свободный от патентных ограничений. |
| **Клеточные автоматы** | Узоры клеточных автоматов. |
| **Градиент с дизерингом** | Плавный двухцветный градиент, к которому применён дизеринг по палитре документа, поэтому результат остаётся в пределах палитры. |

Каждый генератор — **чистая детерминированная функция своих параметров и начального
значения**: одно и то же начальное значение и одни и те же параметры всегда дают один и тот же
результат. Сгенерированное содержимое записывается через **путь обратимых команд**, поэтому
любая генерация — один шаг отмены. Размер результата по каждой оси ограничен платформенным
пределом размера для процедурной генерации.

## Обратимость и отзывчивость

Любая автоматизация — воспроизведение макроса, запуск скрипта, пакетная перекраска,
процедурная заливка — попадает в **обычный стек отмены как один шаг**, поэтому вы можете
откатить любую из них. В графическом интерфейсе автоматизация выполняется в **фоновом рабочем
потоке** с детерминированным завершением работы, поэтому длинный пакет или большая
процедурная заливка не замораживают окно.

## Командная строка `pixelart-run`

Для автоматизации и CI `pixelart-run` воспроизводит `.pixmacro` для проекта `.pixproj` **без
графического интерфейса** через **тот же самый** доверенный диспетчер, которым управляет
интерфейс, — поэтому итоговый документ **идентичен по состоянию** документу, полученному при
запуске той же автоматизации с теми же входными данными в графическом интерфейсе.

```
pixelart-run --input PROJECT.pixproj --macro MACRO.pixmacro --output OUT.pixproj [options]
```

| Флаг | Значение |
| --- | --- |
| `--input PATH` | **(обязательно)** исходный проект `.pixproj`, над которым выполняется макрос. |
| `--macro PATH` | **(обязательно)** воспроизводимый макрос `.pixmacro`. |
| `--output PATH` | **(обязательно)** путь `.pixproj`, в который записывается результат. |
| `--seed N` | переопределяет начальное значение для операций, у которых оно не записано (записанное начальное значение всегда имеет приоритет). |
| `--param KEY=VALUE` | задаёт или переопределяет параметр макроса; можно повторять. |

**Коды завершения:** `0` — успех; `1` — сбой автоматизации (ошибка скрипта / макроса / пакета /
процедурной генерации либо сбой записи); `2` — неверные аргументы либо некорректный /
нечитаемый входной проект или макрос.

> **Консольная точка входа.** `pixelart-run` устанавливается как консольный скрипт при
> `pip install`.

## Что не охвачено

- **Произвольные скрипты на Python** — **не поддерживаются по замыслу.** Скрипты — это
  ограниченный командный DSL с белым списком, а не интерпретатор общего назначения; это
  намеренная граница безопасности, а не ограничение, которое предстоит снять.
- **Изоляция недоверенных сторонних плагинов** — **отложена.** У плагинов в этом выпуске нет
  песочницы; устанавливайте и включайте только те плагины, которым вы доверяете.
