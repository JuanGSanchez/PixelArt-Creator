# 导出与管线集成

**导出系统**会把项目转换成游戏管线所需的素材：单张 **PNG** 图像、一段 **GIF 动
画**、**精灵表**或打包而成的**纹理图集**，每一种都可以附带 **Aseprite 样式
的 JSON** 元数据，还有可直接放入项目的 **Unity** 和 **Godot** **引擎预设**。你可以在
导出对话框中导出一个目标，用批量面板一次处理多个目标，也可以通
过 `pixelart-export` 命令行以无界面方式运行整个流程，同时每一种方式产生的都是**相同
的字节**。要打开导出对话框，请选择**文件 ▸ 导出…**，也可以使用快捷
键 **Ctrl+Shift+E** 来打开。

> **字节可复现的导出**。导出是**确定性的**：对于固定的输入文档和相同的参数，输出的字
> 节每次都完全一致——帧按明确的顺序遍历，而 GIF 使用固定的共享调色板并关闭抖动，编码
> 器的版本也是固定的。图形界面和命令行驱动的是**同一个**引擎，所以对同一文档进行
> 的 GUI 导出和 CLI 导出**字节完全相同**。这一保证针对的是*同一环境*（固定的工具
> 链），并不保证在不同的机器之间也成立。

| 快捷键 | 操作 |
| --- | --- |
| **Ctrl+Shift+E** | 打开导出对话框。 |

## PNG / GIF 光栅导出

- **PNG** 把**第 0 帧**导出为单张 RGBA 图像——这是单帧图像目标。
- **GIF** 导出动画：按顺序导出每一帧，每一帧都按它自己的**每帧时长**显示（即
  在[动画时间轴](animation-timeline.md)上设置的时长），并把循环次数、帧处置方式和透
  明度写入文件。所有帧共用**一个固定的调色板**（对整个动画做中位切分来缩减颜色），同
  时抖动**已关闭**，这正是 GIF 能做到字节可复现的原因。

> **GIF 循环次数**。`--loop` 标志（用于命令行）/ **循环次数**字段（用于对话框）设
> 置 GIF 重复播放的次数，其中 **`0` 表示永久循环**。

## 精灵表与纹理图集

- **精灵表**把每一帧排布在**统一的网格**上，按行优先顺序排列——第 `k` 帧位于
  第 `k % columns` 列、第 `k // columns` 行，精灵之间的**间距**可以配置，外部没有边
  距。设置列数即可控制精灵表的形状。
- **纹理图集**使用共享的 **MaxRects** 打包器，把每一帧密集地打包在一起（旋转功能已关
  闭，所以精灵始终与坐标轴对齐）。当帧的内容大小不一时，图集是占用空间更少的选择。

> **图集尺寸上限**。图集的大小受平台 **8K** 尺寸上限的约束。如果一组精灵无法放入这个
> 上限之内，导出会**安全地失败**并给出明确的图集错误（绝不会出现悄悄发生的重叠、内容
> 缺失或崩溃）——请减小间距、帧尺寸或帧数，之后重试。

## JSON 元数据

精灵表和图集导出可以生成一个 **JSON 元数据附属文件**，采用 **Aseprite *Array*** 格
式：一个 `frames[]` 数组（包含每一帧的矩形区域、源尺寸和时长），以及一
个 `meta{}` 块，其中记录帧**标签**和每帧时长。该 JSON 是**确定性的**——键已排序，分隔
符固定，坐标均为整数——因此可以往返转换，用差异对比工具比较时也不会出现多余的差异。你可以用对话框中
的**写入 JSON 元数据**复选框来开关它，也可以在命令行上使用 `--json` / `--no-json` 选
项（默认开启）。

## Unity / Godot 引擎预设

除了图像和 JSON 以外，导出还可以写出一个**可直接用于引擎的预设**，使素材可以直接放入
项目：

| 预设 | 写出的内容 |
| --- | --- |
| **Unity** | 一个精灵 `.meta` 附属文件，写入 **Multiple** 精灵模式，同时写入轴心点和 `pixelsPerUnit` 参数，以及 `filterMode = Point` 设置（边界分明的像素，没有双线性平滑）。 |
| **Godot** | 一个基于导出的帧生成的、适用于 Godot 4.2 的 `SpriteFrames` `.tres` 资源。 |

你可以在对话框中选择预设，也可以在命令行上传
入 `--preset unity` 或 `--preset godot` 参数；默认值 `--preset none` 不会写出任何预
设。预设文件是根据与图像相同的布局元数据，以确定性方式构建的。

## 批量导出

**批量导出面板**可以**一次处理多个目标**——例如在一次运行中，从同一个项目导出一
个 PNG 图像、一个 GIF 动画和一个 Unity 图集。批量导出采用**失败后继续**的方式：如果
某个目标失败（比如某个图集放不下），其他目标还会照常导出，失败只会针对该目标单独报
告，所以一个有问题的目标绝不会中止整次批量导出。**全部导出**按钮会把当前标签页中的文
档导出到目标列表中的每一个目标，一次运行即可完成。

## 将导出的文件登记到素材库

导出对话框中有一个复选框，**同时添加到素材库**，它会在导出的同一步骤中，把导出的文件
登记到[素材库](asset-library.md)中——这是需要主动选择的选项，而不是默认行为。勾选
后，导出成功之后会打开共用的**登记素材**提示（名称、类型、标签）；不勾选时，导出完全
不会改动素材库，与这个选项出现之前完全一样。

## 界面保持响应

所有导出工作都**不在 GUI 线程上**，而是在后台工作线程上运行，并带有一个**可以取消的
进度指示器**——所以导出大型动画或图集时，窗口绝不会失去响应。导出对你的文档是**只
读**的：它绝不会修改文档，也不会产生任何撤销步骤。

> **取消大型的单个目标**。取消会在目标之间及时生效；不过在**单个大型目标的编码过程
> 中**取消，取消的粒度较大——正在进行的编码会先完成，之后才会响应取消。

## `pixelart-export` 命令行

`pixelart-export` 用于自动化和 CI 场景，它会在没有图形界面时运行**完全相同的**导出路
径——它的输出与同一文档、同一参数的 GUI 导出按字节完全一致。它通过应用所用的、带防御
式校验的同一个项目加载器来加载 `.pixproj` 文件。

```
pixelart-export --input PROJECT.pixproj --format FORMAT --output OUT [options]
```

| 标志 | 说明 |
| --- | --- |
| `--input PATH` | （**必填**）要导出的源 `.pixproj` 项目。 |
| `--format FORMAT` | （**必填**）取值为 `png`, `gif`, `sprite-sheet`, `atlas` 之一。 |
| `--output PATH` | （**必填**）输出图像的路径。 |
| `--preset PRESET` | 引擎预设，默认值 `none` 表示不写出预设，也可以取 `unity` 或 `godot` 之一。 |
| `--columns N` | 精灵表的列数。 |
| `--padding N` | 精灵之间的间距，以像素为单位。 |
| `--loop N` | GIF 循环次数，其中 `0` 表示永久循环。 |
| `--tag NAME` | 只导出某个已命名帧标签所覆盖的范围，默认导出整个文档。 |
| `--json` / `--no-json` | 是否输出精灵表 / 图集的 JSON 附属文件，默认开启。 |

**退出码**： `0` 表示成功； `1` 表示导出 / 打包 / 写入错误（例如图集无法放下，或文件
系统写入失败）； `2` 表示参数错误，或输入的项目格式错误 / 无法读取。

> **与 GUI 路径相同**。由于命令行和对话框调用的是同一个引擎，你可以先交互式地试做一
> 次导出，之后在构建脚本中把相同的参数作为标志传入，精确地重现它。

## 未涵盖的内容

- **APNG** 格式（即动画 PNG 格式）——**留待以后实现**；当前版本导出单帧的 PNG 图
  像（第 0 帧）和 GIF 动画。
- **跨机器字节完全相同**的输出——字节可复现性保证针对的是*同一环境*（固定的工具
  链）；不同机器的工具链可能会产生不同的字节。
- 对单个大型目标进行**编码过程中的细粒度取消**——取消只会在目标之间响应，而不会在某个
  目标的编码进行到一半时响应。
