# 自动化、宏、脚本与插件

**自动化系统**使你可以录制、编写脚本、重放和批量运行编辑器自带的操作，还可以以程序化
方式生成内容——所有这些都通过**同一个**引擎完成，这个引擎由 GUI 和无界面
的 `pixelart-run` 命令行共用，所以无论你是从面板启动自动化，还是从构建脚本启动，它的
运行结果都**完全一致**。

> **设计即安全——永远不使用 `eval` 调用**。脚本是一种**有界的、由数据驱动的 DSL 命令
> 集**，而不是任意的 Python 代码。一次自动化是一个*已校验的操作列
> 表*（`{name, params, seed}`），绝不是一门语言：在这条路径上，**任何地方都不会对你
> 的输入使用 `eval` / `exec` / `compile` / `__import__`**——这里没有可以跳出的解释
> 器。单一的受信任调度器会先根据**允许列表**检查每个操作的名称，并根据声明的参数结构
> 检查其参数，之后才构建它所对应的可撤销命令。

## 宏——录制、重放与 `.pixmacro` 格式

**宏**面板会录制你所执行的操作，并在以后重放它们：

- **录制宏**会捕获每一步的*输入*——已解析的参数，以及对任何随机步骤而言的**种子**——而
  不是像素差异。你录制的内容，即是重放时重新运行的内容。
- **重放**会把录制的操作重新应用到当前文档，并只算**一个撤销步骤**，所以一次撤销即可
  撤回整个宏。

宏会存储为 **`.pixmacro`** 文件，它是 JSON 文本，带有版本信息的外层封装：

```
{
  "format": "pixmacro",
  "schema_version": "1",
  "min_app_version": "0.8.0",
  "api_version": "1",
  "ops": [
    { "op": "batch_recolour", "params": { }, "seed": null },
    { "op": "procgen",        "params": { }, "seed": 12345 }
  ]
}
```

- **`schema_version` / `api_version` / `min_app_version`** 会在加载时检查：未知或不
  受支持的版本会**明确地失败**，并给出一条说明原因的错误，而不是错误地重放。
- **`params`** 是 JSON 原生类型，所以保存再加载一个宏会得到**完全相同**的宏——颜色和
  索引映射以列表形式保存。
- **`seed`** 会为每个随机步骤记录下来，所以重放是可复现的。

> **确定性重放**。在相同的起始文档上两次重放同一个宏，会得到**状态完全一致**的文
> 档。每个随机步骤都只从它所记录的种子中取随机数——不使用系统时间，不使用未设种子的随
> 机性，也不依赖区域设置。这正是宏可以放心地在构建管线中运行的原因。

加载 `.pixmacro` 文件是**防御式**的：每个字段都会接受类型、范围和版本检查，格式错误
或超出范围的文档会引发明确的错误，其内容**绝不会**被传给 `eval`/`exec` 去执行。

## 运行脚本

**脚本运行器**会通过宏重放所使用的同一个受信任调度器来分发一组操作。一次脚本运行
是**原子性的**：

1. **所有操作都会预先校验**——在**任何内容被应用之前**，所有操作名称都会对照允许列表
   检查，所有参数都会对照其结构检查。
2. 整次运行会作为**一个分组的、可撤销的命令**被应用。
3. 如果任何一个操作在执行到一半时失败，已应用的操作会**按相反的顺序回滚**，所以一次
   失败的多操作运行会使文档**保持不变**——绝不会只应用了一半。

由于整次运行是一个分组命令，所以一个已完成的脚本是**单个撤销步骤**。

## 插件——管理器、用户同意与信任模型

**插件**面板会列出插件，显示你已加载清单的各个插件所声明的权限，并可启用和禁用这些插
件。插件的设计目的，是通过注册新的 DSL 操作来扩展编辑器。**在当前版本中，应用没有任
何步骤会加载或运行插件的代码**：发现插件、加载清单、启用和禁用，都不会调用任何插
件。清单所声明的权限，说明的是插件设想的用法；它们并不限制插件本身的代码能做哪些
事（参见下面的说明）。

- **发现只会列出插件**。应用通过标准的 Python 入口点找到已安装的插件，不过只会读取它
  们的名称和版本：它**不会**加载或运行它们的代码。已发现的插件不显示任何权限，也无法
  被启用，因为应用不会从插件本身读取权限。权限来自你从硬盘添加到面板中的清单文件，该文件
  会在列表中显示为单独的一项。应用不会检查某个清单是否属于你已安装的某个插件。
- **同意的范围是清单，而不是插件的代码**。**启用**会显示清单所声明的权限，并请你确
  认。你只能把这些权限作为一个整体批准，否则不启用该插件。应用不会对照插件代码实际所
  做的事情来检查清单。启用操作会在内存中记录你已批准的权限，并把该插件标记为已启
  用；它不会运行插件的代码，因为应用没有任何会运行插件代码的步骤。你的同意不会被保
  存：每个插件在你关闭编辑器时都会再次被禁用。插件宿主的设计是这样的：如果某个调用方给
  了它在插件被启用时运行的代码，这段代码就会得到一个权限对象，而通过该权限对象发出的
  未被授予的调用会被拒绝；但在当前版本中，没有任何部分会给它这样的代码。通过该权限对
  象注册的操作，名称前会加上插件的名称，所以它们不会与内置操作的名称相同。此外，通过它
  使用读取权限时，得到的是传入的文档，而不是副本。不通过该权限对象的代码不受它的限
  制：它可以直接注册或移除操作，包括内置操作在内。
- **禁用移除的是操作，而不是插件的代码**。**禁用**会取消注册通过权限对象注册的操
  作；在当前版本中没有这样的操作，因为没有任何部分会注册它们。禁用不会撤销插件本身的
  代码已做过的任何事情。

> **插件没有沙盒隔离**。插件并没有与你的计算机隔离开，在当前版本中，应用也没有对任
> 何插件做隔离。安装插件会把别人的 Python 代码放到你的计算机上，应用不会执行这次安
> 装，也不会对其进行检查。此外，一个 Python 包可以使 Python 每次在该包所安装的环境中
> 启动时运行代码，这也包括编辑器的启动，所以仅仅安装一个插件，也可能使它的代码运
> 行，即使你从未打开**插件**面板。在编辑器进程中运行的代码，无论它是以何种方式进入进
> 程的，对你的文件和网络都具有与编辑器相同的访问权限，不管插件声明了哪些权限。请只安
> 装并启用你信任的插件。

## 批量重新着色

**批量重新着色**会把一次颜色重映射**同时应用到许多目标**，并作为**单个事务性的、可撤
销的命令**：

- 对于**索引**目标，它会按 `old_index → new_index` 重映射调色板索引；对
  于 **RGBA** 目标，它会按 `old_rgba → new_rgba` 重映射颜色。它复用了编辑器现有的重
  新着色操作，所以批量处理中的某个目标，与使用同一映射单独对该目标重新着色，结果
  是**字节完全相同**的。
- 它是**事务性的**：每个目标都会先通过校验，并先构建出每个目标的步骤，**之后才会应用
  任何内容**。如果目标无效，会指出出错的目标并失败，**不会有任何改动**。整批操作
  是**一个撤销步骤**。

## 程序化生成

**程序化生成**面板会用生成的内容填充一个区域。有五种自行实现的、**带种子的**生成器可
用：

| 生成器 | 产生的内容 |
| --- | --- |
| **值噪声** | 带种子的值网格噪声。 |
| **梯度噪声** | Perlin 式的梯度噪声。 |
| **OpenSimplex 噪声** | 一种没有专利问题的、基于 simplex 网格的梯度噪声。 |
| **元胞自动机** | 元胞自动机图案。 |
| **抖动渐变** | 一种平滑的双色渐变，按文档调色板做了抖动，因此结果始终保持在调色板之内。 |

每个生成器都是**只由其参数和种子决定的确定性计算**——相同的种子和参数总是产生相同的输
出。生成的内容会通过**可撤销命令路径**写入，所以任何一次生成都是单个撤销步骤。输出在
每个轴向上都受平台的程序化生成尺寸上限约束。

## 可撤销与保持响应

每一项自动化——宏重放、脚本运行、批量重新着色、程序化填充——都会**作为一个步骤进入正常
的撤销历史记录**，所以你可以撤回其中任何一项。在 GUI 中，自动化会在**后台工作线
程**上运行，并以确定的方式完成线程清理，所以长时间的批量操作或大范围的程序化填充不会使窗口
失去响应。

## `pixelart-run` 命令行

`pixelart-run` 用于自动化和 CI 场景，它会以**无界面**方式（不启动图形界面）重
放 `.pixmacro` 宏，并把它应用到 `.pixproj` 项目上，使用的是 GUI 所用的**完全相同
的**受信任调度器，所以得到的文档与 GUI 对同一输入运行同一自动化的结果**状态完全一
致**。

```
pixelart-run --input PROJECT.pixproj --macro MACRO.pixmacro --output OUT.pixproj [options]
```

| 标志 | 说明 |
| --- | --- |
| `--input PATH` | （**必填**）要在其上运行宏的源 `.pixproj` 项目。 |
| `--macro PATH` | （**必填**）要重放的 `.pixmacro` 宏。 |
| `--output PATH` | （**必填**）用于写入结果的 `.pixproj` 路径。 |
| `--seed N` | 为未记录种子的操作覆盖种子（已记录的种子始终优先）。 |
| `--param KEY=VALUE` | 传入或覆盖一个宏参数；可以重复使用。 |

**退出码**： `0` 表示成功； `1` 表示自动化失败（脚本 / 宏 / 批量处理 / 程序化生成出
错，或写入失败）； `2` 表示参数错误，或输入的项目或宏格式错误 / 无法读取。

> **控制台入口点**。命令 `pixelart-run` 会在执行 `pip install` 时被安装为控制台脚
> 本。

## 未涵盖的内容

- **任意的 Python 脚本**——**按设计不支持**。脚本是一种有界的、受允许列表限制
  的 DSL 命令集，而不是通用解释器；这是一条有意设置的安全边界，而不是将来要取消的局
  限。
- **对不可信的第三方插件的隔离**——**留待以后实现**。插件在当前版本中没有沙盒隔
  离；请只安装并启用你信任的插件。
