| Field | Value |

| Superseded by | — |
| Relates to | ADR-0047 (`tests/scripts/`), ADR-0043 (`tests/deploy/`), ADR-0049 (`tests/memory_view/`) |

## Context

ADR-0048 was written one day earlier, on 2026-08-15, and its central premise
does not survive checking.

It recorded that six undeclared commits had reached the default branch through
the pre-commit gate's furniture exemption, and concluded the exemption was a
hole. Classifying those six commits afterwards gives a different picture:

```
115df87 chore(memory): refresh the map after the merge          <- post-merge hook
1fa24ac chore(memory): refresh the map index after the merge    <- post-merge hook
eb23ed2 chore(memory): compact the map after the merge          <- hand-committed
94093e1 chore(memory): re-observe the fidelity fixture          <- hand-committed
1a5f6d5 chore(memory): re-scan this branch's own store          <- hand-committed
e4f788d chore(githooks): commit the hook set the container installs <- hand-committed
```

**Two of the six are `post-merge` doing what the arrangement requires.** The
canonical generator is explicit that the refreshed map must be committed on the
default branch and not left dirty, because the next merge would otherwise
refuse to overwrite it — and on a product's `main` a merge is the only way work
ever arrives. Those two commits are the design working.

**The other four were hand-committed on `main` by an agent.** That is a
discipline failure upstream of the gate, not a defect in it.

**And `.githooks/*` is generated, not authored.** Every one of those files
carries the header *"generated by `container_repo.py`; re-generate with
`container_repo.py install-hooks`, never hand-edit."* ADR-0048's decisions were
implemented by editing them directly. The next `start-branch` regenerated the
canonical hooks over the edit — correctly — and the resulting test failures on
the new branch were then read as a second regression, in the generator. They
were not. The generator was right both times.

**The marker was also a second source of truth.** The canonical gate derives
its exemption from one list:

```python
FURNITURE = (".githooks", ".gitattributes", "memory")
FURNITURE_PATTERN = "^({})(/|$)".format(...)
# "Derived, never a second list: an exemption that drifted from the pathspec
#  would refuse the commit that installs the very files the pathspec protects."
```

`PIXELART_MAIN_BOOKKEEPING` sat beside that list as an independent condition
governing the same decision, which is the arrangement the generator's own
comment exists to prevent.

## Decision

**1. The marker is withdrawn.** `.githooks/pre-commit` and `.githooks/post-merge`
are restored to exactly what `container_repo.py install-hooks --profile product`
generates, verified by regenerating them and comparing bytes. A store-only
commit on the default branch is admitted as the arrangement, as it was before.

**2. Generated files are regenerated, never hand-edited.** A change wanted in
these hooks is a change to the generator, which is a container-level artifact
under copy-fidelity gating — and therefore a change to be proposed upstream,
not made locally in the output.

**3. What actually keeps work off the default branch is the branch-and-pull-request
discipline**, which the gate's refusal message already names and which this
project now follows. No local gate stops somebody who means it; ADR-0048 said
so itself while adding a variable that anybody could set.

**4. `tests/githooks/` stays** (ADR-0048 decision 4, unchanged) and is rewritten
to assert the canonical rule: the creation commit, a merge, and the arrangement
are admitted; development is refused; furniture mixed with product code is
development again. A regression test pins the withdrawal itself — setting the
old variable must not change any verdict.

## Consequences

**One test was green for the wrong reason, and is now correct.** The old
parametrised case staged `.githooks/pre-commit` and asserted a non-zero exit.
It passed — but because overwriting the *running* hook makes git fail with
`cannot spawn`, which is indistinguishable from a refusal. The rewritten suite
uses `post-merge` to stand for that root, and says why in a comment.

**The rewritten suite is portable across branches.** The old one asserted the
content of a generated file, so it was green in the checkout whose hooks had
been edited and red in every freshly created worktree. Behaviour is asserted by
driving real commits against whatever hooks this clone actually ships.

**ADR-0048 is not deleted or rewritten.** Its record of the reasoning, and of
where that reasoning failed, is the useful part. Its `Superseded by` field now
names this ADR.
